เนื้อหาบทนี้มุ่งเน้นการปูพื้นฐาน Digital Logic Fundamentals ที่จำเป็นสำหรับการเขียนภาษาบรรยายฮาร์ดแวร์ (VHDL/Verilog) บน FPGA ตั้งแต่ระบบเลขฐาน วงจรตรรกะ Combinational & Sequential ไปจนถึงสถาปัตยกรรม Synchronous Design และการวิเคราะห์ Timing Closure

2 ระบบเลขฐานและการแทนค่าข้อมูล (Number Systems & Data Representation)

ในระบบดิจิทัล สัญญาณไฟฟ้ามีเพียง 2 สถานะคือ HIGH (1) และ LOW (0) การเข้าใจรูปแบบการแทนค่าข้อมูลจึงเป็นจุดเริ่มต้นที่สำคัญในการออกแบบฮาร์ดแวร์:

2.1 เลขฐานสองและเลขฐานสิบหก (Binary & Hexadecimal)

  • Binary System (Base 2): ประกอบด้วยตัวเลข 0 และ 1
    • Bit (Binary Digit): หน่วยที่เล็กที่สุด (0 หรือ 1)
    • Byte: 8 bits (เช่น 1101_0010)
    • Word: ขึ้นอยู่กับสถาปัตยกรรม (16 bits, 32 bits หรือ 64 bits)
  • Hexadecimal System (Base 16): ใช้ตัวเลข 0-9 และ A-F แทนค่า 10-15 โดย 1 Hex Digit จะแทนเลขฐานสองได้ 4 bits พอดี ช่วยให้มนุษย์อ่านบัสข้อมูลขนาดยาวได้ง่ายขึ้น

2.2 การแทนค่าเลขติดลบ (Signed Number Representations)

ในการออกแบบระบบดิจิทัลและการคำนวณใน FPGA การแทนค่าตัวเลขติดลบ (Signed Numbers) สามารถทำได้ 3 วิธีหลัก:

2.2.1 วิธีการแทนค่าเลขติดลบ 3 รูปแบบหลัก

  1. Sign and Magnitude (บิตเครื่องหมาย + ขนาด):

    • ใช้บิตซ้ายสุด (MSB) เป็น Sign Bit (บวกลบ) และบิตที่เหลือเก็บค่าขนาดตัวเลข (Magnitude)
    • ตัวอย่าง (4 บิต): 0101, 1101
    • ข้อเสีย: มีค่า ศูนย์ 2 ค่า (+0 = 0000, -0 = 1000) และสร้างวงจรบวก/ลบทางฮาร์ดแวร์ได้ซับซ้อน

  2. 1's Complement (คอมพลีเมนต์หนึ่ง):

    • สลับบิตทั้งหมดจาก 0 เป็น 1 และ 1 เป็น 0 เพื่อแทนค่าติดลบ
    • ตัวอย่าง (4 บิต): 0101, 1010
    • ข้อเสีย: ยังคงมีค่า ศูนย์ 2 ค่า (+0 = 0000, -0 = 1111) และต้องใช้วงจร End-around Carry ในการบวกเลข

  3. 2's Complement (คอมพลีเมนต์สอง) — ⭐ วิธีมาตรฐานที่นิยมใช้แพร่หลายที่สุด:

    • นำค่า 1's Complement มา บวกเพิ่มด้วย 1
    • ข้อดีสำคัญ:
      • มีค่า ศูนย์เพียงค่าเดียว (0000)
      • สามารถใช้ วงจรบวกฮาร์ดแวร์ (Adder Circuit) ชุดเดียวกัน คำนวณได้ทั้งการบวกและการลบเลข โดยไม่ต้องสร้างวงจรลบแยกต่างหาก ช่วยประหยัดพื้นที่ LUTs ใน FPGA ได้อย่างมาก

2.3 ระบบทศนิยม: Fixed-Point vs Floating-Point

  • Fixed-Point (จุดตรึง): กำหนดตำแหน่งจุดทศนิยมตายตัว (เช่น Q4.4 = 4-bit Integer + 4-bit Fractional)
    • ข้อดี: สังเคราะห์เป็นฮาร์ดแวร์ได้ง่าย ประหยัด LUTs และใช้ DSP Block ทำงานได้เร็วมาก (นิยมสุดใน FPGA)
  • Floating-Point (จุดลอย): ตามมาตรฐาน IEEE 754 (Single Precision 32-bit / Double 64-bit)
    • ข้อดี: ขอบเขตช่วงตัวเลขกว้างมาก
    • ข้อเสีย: วงจรซับซ้อน ใช้ทรัพยากร FPGA สูง และเกิด Latency มากขึ้น

2.3.1 ตัวอย่าง: การแปลงค่าเป็น Fixed-Point (Q4.4)

รูปแบบ Q4.4 หมายถึง 8 บิตทั้งหมด แบ่งเป็น 4 บิตส่วนจำนวนเต็ม (Integer) และ 4 บิตส่วนทศนิยม (Fractional) โดยค่าทศนิยมจะถูกคูณด้วย (Scale Factor) แล้วปัดเป็นจำนวนเต็มก่อนเก็บลงรีจิสเตอร์

ตัวอย่างที่ 1: แปลงเลข เป็น Q4.4

ขั้นตอน การคำนวณ ผลลัพธ์
ส่วนจำนวนเต็ม 0101
ส่วนทศนิยม 1100
รวมเป็น Q4.4 (8 บิต) 0101_1100

สรุปการแบ่งบิต ในรูปแบบ Q4.4:

Integer (4 bits) Fraction (4 bits)
0101 1100

ตรวจสอบย้อนกลับ (Decode): 0101_1100 → Integer = 0101 = 5, Fractional = 1100 = 12 → ค่า ✅ ตรงกับค่าตั้งต้น

ตัวอย่างที่ 2: Signed Fixed-Point ค่าติดลบ (2's Complement, เพิ่ม Sign bit เป็น 9 บิต)

Fixed-Point ที่เป็นเลขติดลบ ยังคงใช้ 2's Complement เช่นเดียวกับเลขจำนวนเต็ม Signed ทั่วไป (ตามหัวข้อ 2.2) เพียงแค่ "จินตนาการ" ตำแหน่งจุดทศนิยมแทรกเข้าไปในบิตแพทเทิร์นเดิมเท่านั้น ตัว Hardware Adder/Subtractor ไม่รู้และไม่สนใจตำแหน่งจุดทศนิยม จึงบวกลบบิตแบบ Binary ปกติเหมือนเดิมทุกประการ

ในตัวอย่างนี้จะเพิ่ม Sign bit อีก 1 บิต นำหน้า Q4.4 เดิม รวมเป็น 9 บิต (เรียกได้ว่าเป็น Signed Q4.4 หรือ 1.4.4 format) เพื่อให้เห็นตำแหน่ง Sign bit แยกออกมาชัดเจนจาก Integer/Fraction

ตัวอย่าง: แปลง เป็น Signed Q4.4 (9 บิต)

ขั้นตอน การคำนวณ ผลลัพธ์
1. หาค่า แบบ 9 บิต (Sign=0 นำหน้า Q4.4 เดิม) (ตามตัวอย่างที่ 1) 0_0101_1100
2. Invert บิตทั้งหมด (ครบ 9 บิต) กลับ 0↔1 1_1010_0011
3. บวก 1 (2's Complement) 1_1010_0011 + 1 1_1010_0100
Sign (1 bit) Integer (4 bits) Fraction (4 bits)
1 1010 0100
ลบ (ส่วนหนึ่งของเลข Signed 9 บิต ไม่แยกตีความเป็น Integer อิสระ)

ตรวจสอบย้อนกลับ: มองทั้ง 9 บิต 1_1010_0100 เป็นเลข Signed 2's Complement (ไม่สนใจจุดทศนิยมก่อน) → MSB=1 → เป็นค่าลบ → คำนวณ Magnitude โดย Invert + บวก 1 กลับ: 1_1010_0100 → invert → 0_0101_1011 → +1 → 0_0101_1100 → หารด้วย Scale Factor → ✅ ตรงกับค่าตั้งต้น

ทำไมเพิ่ม Sign bit เป็น 9 บิต?

การเพิ่ม Sign bit แยกต่างหาก (Sign-Extend) ทำให้เห็นตำแหน่งเครื่องหมายชัดเจนขึ้นในเชิงการอธิบาย แต่ในทางปฏิบัติเวลาออกแบบวงจรจริง มักไม่แยก Sign bit ออกมาต่างหาก — ระบบ Q4.4 แบบ Signed 8 บิตเดิม (ที่ MSB ของ Integer field ทำหน้าที่เป็น Sign bit ไปในตัวอยู่แล้วตามคุณสมบัติของ 2's Complement) ก็เพียงพอและประหยัดบิตกว่า การเพิ่มเป็น 9 บิตจึงเทียบเท่ากับการทำ Sign Extension ของเลข 8 บิตเดิมเท่านั้น

2.3.2 ตัวอย่าง: การแปลงค่าเป็น Floating-Point (IEEE 754 Single Precision)

รูปแบบ IEEE 754 Single Precision (32 บิต) แบ่งเป็น 3 ส่วน: Sign (1 บิต) + Exponent (8 บิต, Bias = 127) + Mantissa (23 บิต)

ตัวอย่าง: แปลงเลข เป็น IEEE 754 Single Precision

2. Normalize (รูปแบบ )
3. หา Sign bit เป็นบวก → Sign = 0
4. หา Exponent (บวก Bias 127)
5. หา Mantissa (ตัดเลข 1 หน้าทิ้ง เติม 0 จนครบ 23 บิต) 0111 → 01110000000000000000000

3 พื้นฐานลอจิกเกตและการทำงานบน FPGA (Basic Logic Gates & FPGA LUT Implementation)

ลอจิกเกตถือเป็น อิฐบล็อกพื้นฐานที่สุดของวงจรดิจิทัล ทั้งหมด ไม่ว่าจะเป็นวงจรประเภท Combinational Logic (ที่ใช้ Gate ประกอบเป็น MUX/Decoder/Adder) หรือ Sequential Logic (ที่ใช้ Gate ในการคำนวณ Next State Logic หน้า Flip-Flop)

ข้อแตกต่างระหว่าง ASIC และ FPGA:

ในวงจรรวมแบบสั่งทำพิเศษ (ASIC) ลอจิกเกตจะถูกสร้างจากทรานซิสเตอร์จริงบนซิลิกอน แต่ใน FPGA ตรรกะเกตทั้งหมดจะถูกสังเคราะห์และจัดเก็บเอาต์พุตไว้ใน Look-Up Tables (LUTs)

XOR (Exclusive-OR) เอาต์พุตเป็น 1 เมื่อ อินพุตต่างกัน A=1, B=0 Y=1 y <= a xor b;
XNOR เอาต์พุตเป็น 1 เมื่อ อินพุตเหมือนกัน A=1, B=1 Y=1 y <= a xnor b;

4.3 Combinational Logic

Combinational Logic คือวงจรที่เอาต์พุตขึ้นอยู่กับ ค่าอินพุตในขณะนั้นทันที (ไม่มีสภาวะความจำ/ไม่ต้องใช้ Clock)

Figure 4-3

4.3.2 ตัวอย่างวงจร Combinational ที่สำคัญใน FPGA

  1. Multiplexer (MUX): สวิตช์เลือกสัญญาณอินพุต 1 จากหลายทางมาออกเอาต์พุต 1 ทาง ตามพิน Select
  2. Demultiplexer (DEMUX): วงจรตรงข้าม MUX กระจายอินพุต 1 ช่องไปยังเอาต์พุตหลายช่อง
  3. Decoder: แปลงรหัสอินพุตขนาด บิตเป็นเอาต์พุตขนาด บิต (เช่น 2-to-4 Line Decoder)
  4. Encoder & Priority Encoder: แปลงสัญญาณหลายช่องให้เป็นรหัสขนาด บิต โดย Priority Encoder จะให้ความสำคัญกับช่องสัญญาณสูงสุดก่อนเสมอ
  5. Binary Adder & Subtractor: วงจรบวกและลบเลขฐานสอง (Half Adder, Full Adder, Ripple Carry Adder, Carry Lookahead Adder)

4.3.2.1 ตัวอย่างโค้ด VHDL สำหรับวงจร Combinational Logic

4.3.2.1.1 4-to-1 Multiplexer (when-else)
-- MUX 4 ออก 1 ใช้รูปแบบ Conditional Signal Assignment (when-else)
o_y <= i_a when i_sel = "00" else
       i_b when i_sel = "01" else
       i_c when i_sel = "10" else
       i_d; -- กรณีอื่นๆ (i_sel = "11")
4.3.2.1.2 2-to-4 Decoder (case-when)
-- แปลงรหัส 2 บิตเป็นสัญญาณ Active-High 4 ช่อง
process(i_sel)
begin
    case i_sel is
        when "00"   => o_dec <= "0001";
        when "01"   => o_dec <= "0010";
        when "10"   => o_dec <= "0100";
        when others => o_dec <= "1000"; -- "11"
    end case;
end process;
4.3.2.1.3 4-bit Binary Unsigned Adder
library IEEE;
use IEEE.STD_LOGIC_1164.ALL;
use IEEE.NUMERIC_STD.ALL;

-- วงจรบวกเลขฐานสองขนาด 4 บิต
o_sum <= std_logic_vector(unsigned(i_a) + unsigned(i_b));

4.4 Sequential Logic

Sequential Logic คือวงจรที่มี สถานะความจำ (Memory State) โดยเอาต์พุตจะขึ้นอยู่กับทั้ง อินพุตปัจจุบัน และ สถานะเดิมในอดีต ผ่านจังหวะสัญญาณนาฬิกา (Clock)

4.4.1 ส่วนประกอบหลักของ Sequential Logic

  1. D Flip-Flop (Data Flip-Flop): เป็น Flip-Flop หลักใน FPGA ข้อมูลอินพุต จะถูกส่งผ่านไปยังเอาต์พุต เฉพาะที่ขอบขาขึ้น (Rising Edge) ของ Clock
  2. Registers: กลุ่มของ Flip-Flop หลายๆ ตัวที่นำมาต่อขนานกันเพื่อเก็บบันทึกชุดข้อมูลหลายบิต (เช่น 8-bit Register, 32-bit Register)
  3. Shift Registers: นำ D Flip-Flop มาต่ออนุกรมกันเพื่อเลื่อนบิตข้อมูลไปทางซ้ายหรือขวาตามรอบ Clock (SISO, SIPO, PISO, PIPO)
  4. Counters: วงจรนับค่า (Binary Counter และ Gray Code Counter สำหรับ Async FIFO)

4.4.1.1 ตัวอย่างโค้ด VHDL สำหรับวงจร Sequential Logic

4.4.1.1.1 D Flip-Flop With Enable & Async Reset
process(clk, rst_n)
begin
    if rst_n = '0' then
        q <= '0';
    elsif rising_edge(clk) then
        if en = '1' then
            q <= d;
        end if;
    end if;
end process;
4.4.1.1.2 8-bit Shift Register (SIPO: Serial-In, Parallel-Out)
process(clk, rst_n)
begin
    if rst_n = '0' then
        s_shift_reg <= (others => '0');
    elsif rising_edge(clk) then
        s_shift_reg <= s_shift_reg(6 downto 0) & i_din;
    end if;
end process;

o_parallel_data <= s_shift_reg;
4.4.1.1.3 8-bit Up/Down Binary Counter
process(clk, rst_n)
begin
    if rst_n = '0' then
        s_cnt <= (others => '0');
    elsif rising_edge(clk) then
        if i_up_down = '1' then
            s_cnt <= s_cnt + 1; -- นับขึ้น
        else
            s_cnt <= s_cnt - 1; -- นับลง
        end if;
    end if;
end process;

o_count <= std_logic_vector(s_cnt);

4.4.2 ข้อควรระวัง: การเผลอสร้าง Latch (Unintentional Latch Inference)

Latch เป็นวงจร Sequential อีกชนิดหนึ่งที่ต่างจาก Flip-Flop ตรงที่ Transparent ตามระดับสัญญาณ (Level-Sensitive) ไม่ใช่ที่ขอบสัญญาณนาฬิกา (Edge-Sensitive) แบบ Flip-Flop โดยทั่วไป FPGA Design ควรหลีกเลี่ยงการใช้ Latch โดยเด็ดขาด เพราะ:

  • LUT/FF Cell ใน FPGA ถูกออกแบบมาให้ทำงานเป็น Edge-Triggered Flip-Flop เป็นหลัก การ Infer Latch มักทำให้ต้องใช้ทรัพยากรพิเศษหรือทำงานได้ไม่เต็มประสิทธิภาพ
  • Latch วิเคราะห์ Timing (Static Timing Analysis) ได้ยากกว่า Flip-Flop มาก เสี่ยงเกิด Glitch/Race Condition
  • เครื่องมือ Synthesis (Vivado/Quartus) มักแจ้ง Warning: Latch inferred ซึ่งเกือบทุกครั้งเป็นสัญญาณว่าโค้ดเขียนผิดพลาด ไม่ใช่ตั้งใจ

สาเหตุที่พบบ่อยที่สุด: เขียน process แบบ Combinational (ไม่มี Clock ใน Sensitivity List) แต่ กำหนดค่า Output ไม่ครบทุกเงื่อนไข (Incomplete Assignment) ทำให้ Synthesis Tool ต้อง "จำ" ค่าเดิมไว้เมื่อไม่เข้าเงื่อนไขใดเลย ซึ่งพฤติกรรมการจำค่านี้คือคุณสมบัติของ Latch

-- ตัวอย่างโค้ดที่ผิด (เผลอสร้าง Latch)
process(sel, a, b)
begin
    if sel = '1' then
        y <= a;
    end if;
    -- ผิด! ไม่มี else กรณี sel = '0' ทำให้ Synth ต้องจำค่า y เดิมไว้ -> Infer Latch
end process;

-- ตัวอย่างโค้ดที่ถูกต้อง วิธีที่ 1 (แก้โดยกำหนดค่า Default ก่อนเสมอ)
process(sel, a, b)
begin
    y <= b; -- Default assignment กันไว้ก่อนเสมอ
    if sel = '1' then
        y <= a;
    end if;
end process;

-- ตัวอย่างโค้ดที่ถูกต้อง วิธีที่ 2 (แก้โดยใช้ else ปิดให้ครบทุกเงื่อนไข)
process(sel, a, b)
begin
    if sel = '1' then
        y <= a;
    else
        y <= b;
    end if;
end process;

5 การออกแบบสัญญาณนาฬิกาและรีเซ็ต (Clock & Reset Design)

สัญญาณนาฬิกาและรีเซ็ตถือเป็น หัวใจหลักของการควบคุมระบบ Synchronous System ทั้งหมดใน FPGA

5.1 สัญญาณนาฬิกาและ Synchronous Design Standard

  • Clock Signal: สัญญาณนาฬิกากำหนดจังหวะการทำงานของระบบ โดยใน FPGA ต้องส่งผ่าน Global Clock Trees เพื่อให้สัญญาณกระจายถึง Flip-Flop ทุกตัวด้วยค่า Clock Skew ต่ำที่สุด
  • Clock Skew: ความเหลื่อมเวลาของสัญญาณนาฬิกาที่เดินทางไปถึง Flip-Flop แต่ละตัว
Figure 5-1
  • Clock Domain: ขอบเขตสัญญาณนาฬิกา สัญญาณที่เดินทางข้าม Clock Domain ต่างความถี่ เรียกว่า CDC (Clock Domain Crossing) ต้องใช้ Synchronizer หรือ FIFO กั้นเพื่อป้องกันข้อมูลผิดพลาด

5.1.2 วงจร Synchronizer สำหรับสัญญาณ 1 บิต (2-Flip-Flop Synchronizer)

เมื่อสัญญาณ 1 บิต (เช่น Flag หรือ Status bit) ต้องเดินทางข้าม Clock Domain การป้อนสัญญาณเข้า Flip-Flop ปลายทางตรงๆ มีความเสี่ยงสูงที่จะทำให้เกิด Metastability (ตามที่กล่าวในหัวข้อ 7.2) เนื่องจากสัญญาณอาจเปลี่ยนค่าในช่วง Setup/Hold Window ของ Flip-Flop ปลายทางพอดี

วิธีแก้ที่นิยมและง่ายที่สุดคือ 2-Flip-Flop Synchronizer: นำสัญญาณผ่าน Flip-Flop 2 ตัวเรียงต่อกันในโดเมน Clock ปลายทาง เพื่อให้เวลา (1 Clock Period) สำหรับสถานะ Metastable ที่อาจเกิดขึ้นที่ FF ตัวแรกได้ "สงบ" ลงก่อนที่จะถูกอ่านค่าโดย FF ตัวที่สอง

-- 2-FF Synchronizer: ซิงค์สัญญาณ 1 บิต (i_async_signal) จาก Clock Domain อื่น
-- เข้าสู่ Clock Domain ปลายทางที่ขับด้วย clk_dst
process(clk_dst, rst_n)
begin
    if rst_n = '0' then
        s_sync_ff1 <= '0';
        s_sync_ff2 <= '0';
    elsif rising_edge(clk_dst) then
        s_sync_ff1 <= i_async_signal;  -- FF ตัวแรก: จุดเสี่ยง Metastability
        s_sync_ff2 <= s_sync_ff1;      -- FF ตัวที่สอง: ให้เวลา Settle ก่อนใช้งานจริง
    end if;
end process;

o_sync_signal <= s_sync_ff2; -- นำสัญญาณที่ Sync แล้วไปใช้งานต่อในโดเมนนี้
ข้อจำกัดสำคัญ:

2-FF Synchronizer ใช้ได้เฉพาะสัญญาณ 1 บิต หรือสัญญาณที่เปลี่ยนค่าไม่พร้อมกันได้ (เช่น Single-bit Pulse/Flag) เท่านั้น ห้ามใช้กับบัสข้อมูลหลายบิต (เช่น Counter value หรือ Bus data) โดยตรง เพราะแต่ละบิตอาจ Synchronize เสร็จไม่พร้อมกัน ทำให้ค่าที่อ่านได้ผิดเพี้ยน (Bit Skew) — กรณีข้อมูลหลายบิตข้าม Clock Domain ต้องใช้ Async FIFO หรือเทคนิค Handshake แทน

5.2 สัญญาณรีเซ็ต (Reset Signal Design)

ใช้สำหรับกำหนดสถานะเริ่มต้น (Initial State) ให้กับ Flip-Flop ตอนเปิดเครื่องหรือรีสตาร์ทระบบ:

Table 5-1
ประเภท Reset วิธีการทำงาน ข้อดี ข้อเสีย / สิ่งที่ต้องระวัง
Synchronous Reset ทำงานเฉพาะตอนมี Clock Edge มาถึงเท่านั้น • ป้องกันสัญญาณ Noise รบกวน
• ช่วยให้วิเคราะห์ Timing ได้ง่าย		 • ต้องมี Clock วิ่ง วงจรจึงจะรีเซ็ตได้

  • Active High (rst): ทำงานเมื่อสัญญาณเป็น '1'
  • Active Low (rst_n): ทำงานเมื่อสัญญาณเป็น '0' (นิยมใช้เป็นมาตรฐานอุตสาหกรรม)

5.2.2 ตัวอย่างโค้ด VHDL เปรียบเทียบ Synchronous Reset vs Asynchronous Reset

5.2.2.1 Synchronous Active-Low Reset (rst_n)

process(clk)
begin
    if rising_edge(clk) then
        if rst_n = '0' then -- เช็ค Reset ตามจังหวะ Clock
            q_out <= (others => '0');
        else
            q_out <= d_in;
        end if;
    end if;
end process;

5.2.2.2 Asynchronous Active-Low Reset (rst_n)

process(clk, rst_n) -- ใส่ rst_n เข้า Sensitivity List
begin
    if rst_n = '0' then -- รีเซ็ตทันทีเมื่อ rst_n เป็น '0'
        q_out <= (others => '0');
    elsif rising_edge(clk) then
        q_out <= d_in;
    end if;
end process;

6 Finite State Machines - FSM

FSM คือรูปแบบการออกแบบ Sequential Logic ที่ได้รับความนิยมสูงสุดใน FPGA สำหรับควบคุมลำดับการทำงานและสถิติต่างๆ (Control Logic & Sequencer)

6.1 ประเภทของ FSM: Moore Machine vs Mealy Machine

คุณสมบัติ Moore Machine Mealy Machine
เอาต์พุต (Output) ขึ้นอยู่กับ State ปัจจุบันเท่านั้น ขึ้นอยู่กับ State ปัจจุบัน และ Input
การเปลี่ยนแปลง เอาต์พุต เอาต์พุตเปลี่ยนตามจังหวะ Clock Edge เอาต์พุตเปลี่ยนทันทีเมื่อ Input เปลี่ยน
ความเสี่ยง Spikes/Glitches ต่ำมาก (เอาต์พุตเรียบและเสถียร) มีโอกาสเกิด Glitches หาก Input สั่น
จำนวน State อาจต้องใช้จำนวน State มากกว่า มักใช้จำนวน State น้อยกว่า

6.1.2 ตัวอย่างโค้ด: Moore FSM ควบคุมไฟจราจรอย่างง่าย (Traffic Light)

library IEEE;
use IEEE.STD_LOGIC_1164.ALL;

entity traffic_light_fsm is
    port (
        clk       : in  std_logic;
        rst_n     : in  std_logic;
        o_red     : out std_logic;
        o_yellow  : out std_logic;
        o_green   : out std_logic
    );
end entity;

architecture rtl of traffic_light_fsm is
    -- นิยาม State ทั้งหมดด้วย Enumerated Type (Synthesis Tool จะเลือก State Encoding ให้อัตโนมัติ)
    type state_type is (S_RED, S_GREEN, S_YELLOW);
    signal s_current_state, s_next_state : state_type;
begin

    -- Process 1: State Register (Sequential) - เก็บ State ตามจังหวะ Clock
    p_state_reg : process(clk, rst_n)
    begin
        if rst_n = '0' then
            s_current_state <= S_RED;
        elsif rising_edge(clk) then
            s_current_state <= s_next_state;
        end if;
    end process;

    -- Process 2: Next-State Logic (Combinational) - คำนวณ State ถัดไป
    p_next_state : process(s_current_state)
    begin
        case s_current_state is
            when S_RED    => s_next_state <= S_GREEN;
            when S_GREEN  => s_next_state <= S_YELLOW;
            when S_YELLOW => s_next_state <= S_RED;
            when others   => s_next_state <= S_RED; -- Safe default กัน Latch/Unknown State
        end case;
    end process;

    -- Process 3: Output Logic (Combinational, Moore-style) - ขึ้นกับ State ปัจจุบันเท่านั้น
    p_output_logic : process(s_current_state)
    begin
        o_red    <= '0';
        o_yellow <= '0';
        o_green  <= '0';
        case s_current_state is
            when S_RED    => o_red    <= '1';
            when S_GREEN  => o_green  <= '1';
            when S_YELLOW => o_yellow <= '1';
        end case;
    end process;

end architecture;

  • Clock Period (): ระยะเวลา 1 รอบของสัญญาณนาฬิกา
  • Propagation Delay (): ความหน่วงเวลารอคอยตั้งแต่เปลี่ยนอินพุตจนเอาต์พุตตอบสนอง
  • Setup Window: ช่วงเวลาก่อนขอบ Clock ที่อินพุตต้องนิ่ง

7.1.2 ตัวอย่างรูปคลื่นการทำงานจริง: AXI4-Lite Protocol Waveform

ในการออกแบบระบบบน FPGA ที่เชื่อมต่อกับ Microprocessor (เช่น ARM Cortex ใน Zynq) มาตรฐาน AXI4-Lite ถือเป็นบัสโปรโตคอลมาตรฐานที่นิยมใช้แพร่หลายที่สุด การส่งข้อมูลใน AXI4-Lite อาศัย หลักการ Handshake (VALID / READY)

Figure 7-2 : AXI4-Lite Write Transaction WaveDrom Timing Diagram
กฎทองของการ Handshake ใน AXI Protocol:

"การรับส่งข้อมูลจะเกิดขึ้นสำเร็จ (Transfer Done) เฉพาะในรอบขอบขาขึ้นของ ACLK ที่สัญญาณ VALID = 1 และ READY = 1 พร้อมกันเท่านั้น"

  • VALID (สร้างโดยฝั่งส่ง): บ่งบอกว่าข้อมูล/ที่อยู่บนบัสมีความถูกต้องและพร้อมส่งแล้ว
  • READY (สร้างโดยฝั่งรับ): บ่งบอกว่าปลายทางพร้อมรับข้อมูลเข้าสู่ภายในแล้ว
  • หาก VALID = 1 แต่ READY = 0 ฝั่งส่งจะต้อง ค้างค่าข้อมูลไว้บนบัส (Wait State) จนกว่าฝั่งรับจะยก READY = 1 ตอบกลับมา

7.1.2.2 โครงสร้าง 5 ช่องสัญญาณ (Channels) ของ AXI4-Lite

  1. Write Address Channel (AW): ส่งตำแหน่ง Address ที่ต้องการเขียน (AWADDR, AWVALID, AWREADY)
  2. Write Data Channel (W): ส่งข้อมูล Data ที่ต้องการเขียน (WDATA, WSTRB, WVALID, WREADY)
  3. Write Response Channel (B): รายงานสถานะการเขียนกลับไปยัง Master (BRESP, BVALID, BREADY)
  4. Read Address Channel (AR): ส่งตำแหน่ง Address ที่ต้องการอ่าน (ARADDR, ARVALID, ARREADY)
  5. Read Data Channel (R): ส่งข้อมูลที่อ่านได้กลับไปยัง Master (RDATA, RRESP, RVALID, RREADY)

7.2 ข้อกำหนดเวลา Setup Time และ Hold Time

Clock     : __/‾‾\__/‾‾\__/‾‾\__/‾‾\__
Data Input: ====<  Data Valid  >====
                |<-t_su->|<-t_h->|
Figure 7-3 : Setup Time (t_su) and Hold Time (t_h) Window
  1. Setup Time (): ระยะเวลาขั้นต่ำที่ข้อมูลอินพุตจะต้อง คงที่และนิ่ง ก่อนที่ขอบสัญญาณนาฬิกา (Clock Edge) จะมาถึง
  2. Hold Time (): ระยะเวลาขั้นต่ำที่ข้อมูลอินพุตจะต้อง คงค้างไว้ หลังจากขอบสัญญาณนาฬิกาผ่านไปแล้ว
  3. Metastability (สภาวะไม่เสถียร): หากข้อมูลเปลี่ยนในช่วงเวลา หรือ เอาต์พุตของ Flip-Flop จะตกอยู่ในสถานะกึ่งกลางระหว่าง 0 และ 1 (Uncertain state) ส่งผลให้ระบบล่มหรือทำงานผิดพลาดได้

7.3 Timing Slack & Maximum Frequency ()

  • Timing Constraints File (.sdc / .xdc): ไฟล์บอก EDA Tool ว่า Clock ในระบบมีความถี่เท่าไร (เช่น 100 MHz = 10 ns Period)
  • Data Path Delay (): เวลาที่สัญญาณเดินทางจาก Flip-Flop ต้นทาง ผ่าน LUTs ไปยัง Flip-Flop ปลายทาง
  • Slack (ระยะเวลาคงเหลือ):
    • Positive Slack (): สัญญาณเดินทางทันรอบเวลา (Timing PASSED)
    • Negative Slack (): สัญญาณเดินทางไม่ทัน (Timing VIOLATED) ระบบจะทำงานผิดพลาดที่ความแน่นั้น ต้องลดความถี่ Clock หรือปรับแก้โค้ด
