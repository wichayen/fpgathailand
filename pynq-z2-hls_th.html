Vitis HLS (High-Level Synthesis)

Vitis HLS (High-Level Synthesis) คือเครื่องมือที่แปลงโค้ด C/C++ ให้เป็น HDL (VHDL/Verilog) โดยอัตโนมัติ ผลลัพธ์ส่งออกเป็น IP แล้วนำเข้าไปใช้ใน Vivado ได้

ความเห็นส่วนตัวหลังทดลองใช้งาน:
  • แม้จะแปลงจาก C เป็น HDL ได้ แต่ไม่ได้หมายความว่าเขียนโค้ดแบบไหนก็ได้ เพราะสุดท้ายผู้ใช้ยังต้องเข้าใจว่าโค้ดที่เขียนจะกลายเป็นฮาร์ดแวร์หน้าตาอย่างไร
  • ถึงจะใช้ภาษา C แต่ดูไม่ได้ทำมาเพื่อสายซอฟต์แวร์ น่าจะเป็นเครื่องมือสำหรับสายฮาร์ดแวร์ ไว้สร้างโมดูลคำนวณมากกว่า
  • เหมาะกับงานคำนวณและประมวลผลสัญญาณ/ภาพ เช่น PID, FIR, FFT รวมถึง QNN, BNN ด้าน AI
  • ไม่เหมาะกับงานที่ต้องคุม timing ระดับคล็อก/บิต เช่น คอนโทรลเลอร์ SPI, I2C (ทำได้ แต่เขียน VHDL หรือใช้ IP สำเร็จรูปตรงกว่า)
  • sequence controller ระดับสูงที่ไม่ต้องตรงรอบคล็อกเป๊ะ ๆ อาจใช้ได้ (ยังไม่ได้ลอง)

1 สร้าง IP ด้วย HLS

หลังสร้างโปรเจกต์ HLS แล้ว ลำดับการทำงานพื้นฐานเป็นดังนี้

  1. C SIMULATION
    จำลองในระดับภาษา C ตรวจสอบด้วย C testbench
  2. C SYNTHESIS
    แปลงภาษา C → HDL
  3. C/RTL COSIMULATION
    จำลองในระดับ HDL (ดูรูปคลื่นเอาต์พุตใน Vivado)
  4. IMPLEMENTATION
    บีบอัดสิ่งที่แปลงเป็น HDL แล้วเป็น zip ในฐานะ IP

ก่อนอื่น สร้างโปรเจกต์ HLS โดยคลิก File → New Project

ตั้งค่าตำแหน่งโปรเจกต์และรุ่นของ FPGA

คลิกขวาที่ Source แล้ว Add Source File เพื่อเพิ่ม C Source (สิ่งที่ต้องการแปลงเป็น HDL) ครั้งนี้เพิ่ม SWtoLED.cpp การทดสอบครั้งนี้เป็นการคูณอย่างง่าย เตรียม SW (2bit) สองตัว คูณกัน แล้วแสดงผลที่ LED

คลิกขวาที่ Test Bench แล้ว Add Source File เพื่อเพิ่ม Test Bench (C testbench สำหรับตรวจสอบ) ครั้งนี้เพิ่ม SWtoLED_tb.cpp

เนื้อหาในโปรเจกต์ตอนนี้เป็นประมาณนี้

จากนั้นคลิก Project → Project Settings → Synthesis แล้วเลือก C Source (สิ่งที่ต้องการแปลงเป็น HDL) ครั้งนี้เลือก swtoled

Flow Navigator มีเมนู 4 อย่าง

1.1 C SIMULATION

คลิก C SIMULATION → Run C Simulation เพื่อจำลองในระดับ C โดย C Testbench (SWtoLED_tb.cpp)

1.2 C SYNTHESIS

คลิก C SYNTHESIS → Run C Synthesis แล้วกำหนดความถี่คล็อกที่ต้องการให้ทำงาน (Period)

เมื่อเสร็จแล้ว จะได้รายงานจำนวนลอจิกที่ใช้ของ FPGA และรายงาน timing

เวลา Uncertainty ดูเหมือนจะเป็นเวลาเผื่อ (margin)

1.3 C/RTL COSIMULATION

คลิก C/RTL COSIMULATION → Run Cosimulation

ตั้งค่า Dump Trace: port, Wave Debug: เปิดใช้งาน (Enable)

จากนั้น Vivado จะเปิดขึ้นและแสดงรูปคลื่นการจำลองให้

1.4 IMPLEMENTATION

คลิก IMPLEMENTATION → Export RTL แล้วเลือก Export Format เป็น "Vivado IP"

เมื่อเสร็จ จะได้ไฟล์ export.zip ซึ่ง export.zip นี้สามารถนำเข้า Vivado เป็น IP ได้

Note: ดูเหมือนว่าถ้าไม่ใช้ export.zip แต่ชี้ไปที่โฟลเดอร์ ip ก็ทำได้เช่นกัน

2 ทดสอบ IP ที่สร้างด้วย HLS

แตกไฟล์สิ่งที่ export จาก HLS (Export.zip) ไว้ที่ใดที่หนึ่ง

คลิก Add Repository ใน IP Catalog ของ Vivado แล้วเพิ่ม IP ที่สร้างด้วย HLS

IP ที่เพิ่มเข้าไปจะแสดงตรงนี้

เพิ่ม IP ใน Block design ของ Vivado แล้วเชื่อมต่อกับ SW และ LED ภายนอก คอมไพล์ด้วย Vivado แล้วสร้าง bitstream

ทดสอบบนบอร์ดจริง

1 * 1 = 1 1 * 2 = 2
2 * 2 = 4 3 * 2 = 6

3 HLS Pragmas

HLS แปลงโค้ดภาษา C เป็น HDL โดยรูปแบบที่จะแปลงนั้นกำหนดด้วย Pragma มี Pragma หลายชนิด รายละเอียดดูได้ใน Vitis High-Level Synthesis User Guide UG1399 ด้านล่างนี้อธิบาย Pragma บางส่วน

3.1 Interface

เป็นข้อกำหนดให้อาร์กิวเมนต์ของฟังก์ชัน C เพื่อเชื่อมต่อกับบัส AXI แทนที่จะเป็นสัญญาณ หากเพิ่ม pragma ดังต่อไปนี้ อาร์กิวเมนต์ของฟังก์ชันจะรับ/ส่งข้อมูลผ่านบัส AXI อินเทอร์เฟซ AXI กำหนดเป็น slave, master, stream ได้

โหมด ชนิดบัส ใช้เมื่อ
s_axilite AXI4-Lite slave ให้ CPU (เช่น ARM ใน Zynq) อ่าน/เขียนรีจิสเตอร์ของ IP และควบคุมการทำงาน (start/done)
m_axi AXI4 master ให้ IP เข้าถึงหน่วยความจำ (เช่น DDR) เอง
axis AXI4-Stream ส่งข้อมูลต่อเนื่องระหว่างโมดูล เช่น ภาพ, สัญญาณเสียง

ตัวอย่างการเขียน pragma:

void top(int a, int b, int *result) {
#pragma HLS INTERFACE s_axilite port=a      bundle=CTRL
#pragma HLS INTERFACE s_axilite port=b      bundle=CTRL
#pragma HLS INTERFACE m_axi     port=result bundle=gmem offset=slave
#pragma HLS INTERFACE s_axilite port=result bundle=CTRL
#pragma HLS INTERFACE s_axilite port=return bundle=CTRL   // รีจิสเตอร์ควบคุม ap_start / ap_done
    *result = a * b;
}

มีวิธีเขียน Interface หลายแบบ ตัวอย่างเช่น ถ้าเพิ่ม Interface ให้ C Source ที่ใช้ใน หัวข้อที่ 2 ทดสอบ IP ที่สร้างด้วย HLS ดังภาพ IP ที่ Export จะเป็นแบบนี้ ระบบจะกำหนดแอดเดรสให้อัตโนมัติ

หากไม่ต้องการให้กำหนดแอดเดรสอัตโนมัติ สามารถเพิ่ม offset ได้

3.2 Pipeline

กำหนดว่าจะใช้ pipeline หรือไม่ตอนแปลงด้วย HLS

Note: HLS น่าจะเลือกใช้ pipeline เป็นค่าเริ่มต้น

ตัวอย่างการเปรียบเทียบ:

กรณีมี Pipeline กรณีไม่มี Pipeline
pipeline อัตราการใช้ลอจิก FPGA
มี
ไม่มี

กรณีไม่มี pipeline การคำนวณ output = input * input ใช้ 8CLK ดังนั้นถ้า for loop วน 64 รอบ ผลลัพธ์จะออกหลังจาก 64*8 = 512CLK แต่ถ้าใช้ pipeline ผลลัพธ์จะออกได้เร็วกว่ามาก แต่อัตราการใช้ลอจิกของ FPGA จะมากขึ้นเล็กน้อย

for (int i = 0; i < 64; i++) {
#pragma HLS PIPELINE II=1
    out[i] = in[i] * in[i];
}

II (Initiation Interval) คือจำนวนคล็อกระหว่างการเริ่มรอบ loop รอบถัดไป ถ้า II=1 แปลว่าเริ่มรอบใหม่ได้ทุกคล็อก เวลารวมโดยประมาณคือ

เวลารวม ≈ Latency ของ 1 รอบ + (จำนวนรอบ - 1) × II

จากตัวอย่างข้างต้น (1 รอบใช้ 8CLK, วน 64 รอบ) ถ้า II=1 จะได้ประมาณ 8 + 63 = 71CLK เทียบกับ 512CLK ของกรณีไม่มี pipeline (เป็นค่าประมาณเชิงทฤษฎี ค่าจริงให้ดูจากรายงาน C Synthesis)

3.3 Unroll

เป็นข้อกำหนดให้วงจรคำนวณทำงานแบบขนาน (parallel) เมื่อแปลงวงจร loop เป็น HDL

ตัวอย่างการเปรียบเทียบ:

กรณีไม่ Unroll กรณี Unroll
Unroll อัตราการใช้ลอจิก FPGA
ไม่มี
Factor=2
Factor=4
Factor=8
อัตโนมัติ

Unroll จะกำหนดวงจรขนานตามตัวเลข Factor ตัวอย่างเช่น Factor=2 จะเตรียมวงจรคูณ 2 ชุดเพื่อคำนวณ ดูจากผลลัพธ์แล้ว ผลจะออกเร็วกว่ากรณีไม่ unroll (แน่นอนว่าอัตราการใช้ลอจิกของ FPGA เพิ่มขึ้น)

for (int i = 0; i < 64; i++) {
#pragma HLS UNROLL factor=4      // ไม่ใส่ factor = unroll ทั้งหมด
    out[i] = in[i] * in[i];
}
ข้อควรระวัง: อาเรย์ที่ถูกแมปเป็น BRAM มีพอร์ตอ่าน/เขียนจำกัด (ปกติ 2 พอร์ต) ถ้า unroll แล้วต้องอ่านข้อมูลหลายตัวพร้อมกัน อาจไม่ได้ความเร็วเพิ่มตามที่คาด ต้องใช้ร่วมกับ ARRAY_PARTITION เพื่อแบ่งอาเรย์ให้อ่านได้พร้อมกัน 
#pragma HLS ARRAY_PARTITION variable=in  cyclic factor=4
#pragma HLS ARRAY_PARTITION variable=out cyclic factor=4

3.4 Dataflow

กำหนดวิธีการส่งต่อข้อมูลระหว่างโมดูล ถ้าไม่มี Dataflow จะต้องรอให้ผลลัพธ์ทั้งหมดของโมดูลหนึ่งออกมาก่อนจึงเริ่มคำนวณโมดูลถัดไป แต่ถ้าใช้ Dataflow เมื่อโมดูลแรกมีผลลัพธ์ออกมาบางส่วนแล้ว ก็จะเริ่มคำนวณโมดูลถัดไปได้ทันที

ตัวอย่างการเปรียบเทียบ:

กรณีไม่มี dataflow กรณีมี dataflow
dataflow อัตราการใช้ลอจิก FPGA
ไม่มี
มี

เมื่อใส่ Dataflow เวลาคำนวณจะเปลี่ยนจาก 1539CLK → 513CLK (แน่นอนว่าอัตราการใช้ลอจิกของ FPGA เพิ่มขึ้น)

void top(int in[64], int out[64]) {
#pragma HLS DATAFLOW
    int tmp1[64], tmp2[64];
    stage1(in,   tmp1);
    stage2(tmp1, tmp2);
    stage3(tmp2, out);
}
ข้อควรระวัง: ตัวแปรที่ส่งต่อระหว่างฟังก์ชันควรถูกเขียนโดยฟังก์ชันเดียวและอ่านโดยฟังก์ชันเดียว (single producer / single consumer) HLS จะสร้าง buffer แบบ ping-pong หรือ FIFO คั่นกลาง ซึ่งใช้ทรัพยากรเพิ่ม การใช้ hls::stream ระหว่างฟังก์ชันเป็นวิธีที่พบบ่อย

3.5 สรุป Pragma

Pragma ทำอะไร ผลต่อความเร็ว ผลต่อทรัพยากร FPGA
INTERFACE กำหนดชนิดพอร์ต/บัสของ IP - เพิ่มลอจิกของบัส
PIPELINE ซ้อนการทำงานของแต่ละรอบ loop / ฟังก์ชัน เร็วขึ้นมาก เพิ่มเล็กน้อย
UNROLL ทำ loop แบบขนาน เร็วขึ้นตาม factor เพิ่มตาม factor
DATAFLOW ซ้อนการทำงานระหว่างฟังก์ชัน/โมดูล throughput เพิ่มขึ้น เพิ่ม buffer ระหว่างโมดูล

4 เงื่อนไขการใช้งาน

ใน Vitis High-Level Synthesis User Guide มีหัวข้อ Unsupported C/C++ Constructs โดยสรุปคร่าว ๆ ดังนี้

ข้อจำกัด รายละเอียด
System call ฟังก์ชันที่พึ่ง OS เช่น อ่าน/เขียนไฟล์, printf ใช้ได้เฉพาะใน testbench ไม่ถูกแปลงเป็นฮาร์ดแวร์
Dynamic memory malloc / free / new / delete ใช้ไม่ได้ ต้องกำหนดขนาดอาเรย์ตอนคอมไพล์
Recursion ฟังก์ชันเรียกตัวเองไม่รองรับ ให้เขียนเป็น loop แทน
Pointer มีข้อจำกัด เช่น การ cast pointer ระหว่างชนิดข้อมูลทั่วไป และ pointer ซ้อน pointer ที่พอร์ตของ top function
Undefined behavior ผลของ C simulation กับ RTL อาจไม่ตรงกัน

* รายการที่แน่นอนขึ้นกับเวอร์ชัน ให้ตรวจสอบกับหัวข้อ Unsupported C/C++ Constructs ใน UG1399 ของเวอร์ชันที่ใช้

ap_int<12>    x;     // จำนวนเต็มมีเครื่องหมาย 12 บิต
ap_fixed<16,4> y;    // ทศนิยมคงที่ 16 บิต (จำนวนเต็ม 4 บิต)
