1 Switch debouncing

1.1 ปัญหา Contact Bounce

push button และ slide switch เมื่อกดหรือปล่อย หน้าสัมผัส (contact) จะสั่นกระเด้งเปิด-ปิดหลายครั้งก่อนจะนิ่ง ทำให้สัญญาณมี edge เกิดขึ้นหลายครั้ง เราเรียกปรากฏการณ์นี้ว่า bounce ถ้านำสัญญาณนี้เข้าวงจรโดยตรง FPGA ที่ทำงานระดับ MHz จะอ่านทุก edge เหล่านั้นเป็น "การกดหลายครั้ง" ส่งผลให้เกิดการทำงานผิดพลาดโดยไม่ได้ตั้งใจ เช่น counter นับเกิน หรือ FSM เปลี่ยน state ผิด

ปัญหานี้แก้ได้ทาง hardware ด้วยการใส่วงจร RC กรองสัญญาณ แต่การเพิ่ม component เป็นการเพิ่ม cost และยังเพิ่มพื้นที่บน board ด้วย

1.2 แก้ด้วย logic: Sampling + นับความนิ่ง

เราแก้ปัญหานี้ได้ด้วย logic ใน FPGA โดยไม่ต้องเพิ่มอุปกรณ์ หลักการคือ sampling สัญญาณทุก ๆ 1 ms แล้วตีความว่า "กดจริง" ก็ต่อเมื่อสัญญาณใหม่นิ่งต่อเนื่องครบ N sample เท่านั้น กล่าวคือ ถ้าอ่านได้ 1 ต่อเนื่องครบ N sample จึงตีความว่าเป็น 1 และถ้าอ่านได้ 0 ต่อเนื่องครบ N sample จึงตีความว่าเป็น 0 ส่วนถ้ายังไม่ครบ ให้คง output เดิมไว้

หมายเหตุ: คาบ sampling 1 ms และค่า N เป็นเพียงตัวอย่างที่นิยม ไม่ใช่มาตรฐาน ให้เลือกตามสวิตช์ที่ใช้ เช่น N = 10 ทำให้ output หน่วงประมาณ 10 ms ซึ่งน้อยกว่าที่ผู้ใช้จะรู้สึกได้ (ดูตารางด้านล่าง)

ภาพด้านล่างแสดงตัวอย่างการ sampling ทุก 1 ms เมื่อ N = 5

การเลือกค่า N ต้องรู้ก่อนว่าสวิตช์ bounce นานเท่าไร ตารางด้านล่างสรุปค่าทั่วไปและผลของการเลือกเวลาที่สั้นหรือนานเกินไป

หัวข้อ ค่าทั่วไป
เวลา bounce ของสวิตช์เชิงกล ส่วนใหญ่ไม่เกิน ~10 ms แต่บางตัวแย่กว่านั้นมาก
เวลา stable ที่ใช้ debounce ประมาณ 10–50 ms (นิยมเริ่มที่ ~20 ms)
ถ้าสั้นเกินไป bounce หลุดผ่าน
ถ้านานเกินไป ผู้ใช้รู้สึกว่าปุ่มหน่วง (~50 ms ยังรู้สึกว่าตอบสนองทันที ส่วน ~100 ms เริ่มสังเกตได้)

1.3 FPGA code

หลักการข้างต้นแปลงเป็น logic ใน FPGA ได้ดังนี้

หลักการ สิ่งที่ใช้ใน FPGA
สวิตช์เป็น asynchronous input 2-FF synchronizer กัน metastability (ดูหัวข้อ 7)
sampling สัญญาณทุก ๆ 1 ms counter สร้าง tick (pulse กว้าง 1 clk) ทุก 1 ms
เก็บประวัติ N sample ล่าสุด shift register กว้าง N bit ที่ shift ค่าใหม่เข้าทุก tick
ตีความเป็น 1 หรือ 0 เมื่อนิ่งครบ N sample if / elsif ตรวจว่า shift register เป็น 1 ทั้งหมด หรือ 0 ทั้งหมด (นอกนั้นคงค่าเดิม)

2 ความหมาย D flip flop, D-latch

คุณสมบัติ D Flip-Flop (จากโค้ด rising_edge(clk)) Latch = D-latch (ที่มักเกิดจากโค้ดที่เงื่อนไขไม่ครบ)
สิ่งที่กระตุ้นวงจร ขอบสัญญาณนาฬิกา (Edge-Triggered)
เช่น จังหวะที่ clk เปลี่ยนจาก 0 เป็น 1 เท่านั้น		 ระดับสัญญาณ (Level-Sensitive)
เช่น ทำงานตลอดเวลาที่ Enable เป็น 1
พฤติกรรมการจำค่า จำค่าเดิมไว้ตลอดเวลา ยกเว้นเสี้ยววินาทีที่เป็นขอบขาขึ้น ถึงจะอัปเดตค่าใหม่ จำค่าเดิมไว้เมื่อระดับสัญญาณควบคุมเปลี่ยนเป็น 0 (ปิดประตู)
ความปลอดภัยใน FPGA ปลอดภัย 100% เป็นโครงสร้างหลักที่ FPGA ถูกออกแบบมาให้รองรับ อันตราย เสี่ยงต่อการเกิดสัญญาณรบกวน (Glitch) และคำนวณเวลายาก
ตัวอย่างหน้าตาโค้ด VHDL process(clk)
begin
if rising_edge(clk) then
q <= d;
end if;
end process;		 process(en, d)
begin
if en = '1' then
q <= d;
-- ลืมใส่ else!
end if;
end process;

คำว่า "Latch 1 clk" หรือ "หน่วง 1 clk" ที่คนในวงการ FPGA พูดกันเวลาเห็นโค้ดนี้ เป็นการใช้คำแสลงหรือภาษาพูดที่อาจทำให้สับสน
ในทางฮาร์ดแวร์จริงๆ ตัววงจรไม่ใช่ D-Latch แต่สิ่งที่พวกเขาหมายถึงคือ "พฤติกรรมการกักข้อมูลและส่งออกในสัญญาณนาฬิกาถัดไป"
โดยมีความหมายในแง่การทำงาน 2 ประเด็นหลักๆ ดังนี้:

  1. คำว่า "Latch" ในที่นี้เป็นคำกริยา แปลว่า "ล็อกค่า" (Latch the data)
    เวลาคนพูดว่า "โค้ดนี้จะ Latch ข้อมูลไว้ 1 clk" เขาไม่ได้หมายถึงตัวอุปกรณ์ D-Latch ครับ แต่เขาใช้คำว่า Latch เป็นคำกริยา (Verb) ที่แปลว่า "การล็อก/จับ/สแนปเอาค่าข้อมูล ณ วินาทีนั้นไว้" สัญญาณอินพุต d จะถูก D Flip-Flop ล็อกค่าเอาไว้ตอนขอบขาขึ้น แล้วส่งออกไปที่ q

  2. ผลลัพธ์ทำให้เกิดการ "หน่วงเวลาไป 1 คล็อก" (1 Clock Cycle Delay)
    เนื่องจาก D Flip-Flop จะทำงานเฉพาะจังหวะขอบขาขึ้นเท่านั้น ทำให้ข้อมูลที่เอาต์พุต q จะเปลี่ยนแปลงช้ากว่าอินพุต d ไป 1 สัญญาณนาฬิกาเสมอ คนทำงานสายนี้จึงมักเรียกพฤติกรรมนี้ว่าการ "Latch/Hold ค่าไว้ 1 clk" หรือ "Register ไว้ 1 clk" เพื่อใช้ในการซิงค์ข้อมูลหรือทำ Pipeline ครับ

เปรียบเทียบภาษาพูด VS ภาษาฮาร์ดแวร์

  • ภาษาฮาร์ดแวร์ (ถูกต้องตามทฤษฎี): โค้ดนี้สร้าง D Flip-Flop (ไม่ใช่ D-Latch)
  • ภาษาพูดหน้างาน (ภาษาแสลง): "โค้ดนี้เอาไว้ Latch ค่า d ไว้ 1 clk แล้วค่อยส่งออก q" (หมายถึง การใช้ Flip-flop เก็บค่าและหน่วงเวลาไป 1 คล็อก)

ใน CLB FPGA มี D flip flop (ไม่ใช่ D-latch)

3.1 Metastability คืออะไร

Metastability (สภาวะกึ่งเสถียร) คือสภาวะที่ output ของ flip-flop อยู่ที่ระดับแรงดันกึ่งกลางระหว่าง 0 กับ 1 หรือสั่นไปมา เป็นเวลาหนึ่งก่อนจะ settle เป็น 0 หรือ 1 อย่างใดอย่างหนึ่ง โดยเกิดเมื่อ input ของ FF เปลี่ยนค่า ในช่วงที่ละเมิดข้อกำหนด setup time / hold time
ข้อกำหนด : D flip-flop ต้องการให้ input นิ่งก่อนขอบ clock อย่างน้อย tSU และนิ่งต่อหลังขอบ clock อย่างน้อย tH ถ้า input เปลี่ยนในช่วงนี้ FF จะ sample ไม่สมบูรณ์ ผลคือ output อาจกลายเป็น metastable

พารามิเตอร์ ความหมาย
tSU (setup time) input ต้องนิ่งก่อนขอบ clock อย่างน้อยเท่าไหร่
tH (hold time) input ต้องนิ่งต่อหลังขอบ clock อย่างน้อยเท่าไหร่

ตัวอย่างกรณีไม่ผ่านข้อกำหนด

  1. Setup time violation: D เปลี่ยนก่อนขอบ clock น้อยกว่า tSU

  1. Hold time violation: D เปลี่ยนหลังขอบ clock เร็วกว่า tH

Note : ไม่ใช่ทุกการละเมิด setup/hold จะทำให้เกิด metastable แต่มีความน่าจะเป็นที่จะเกิด

3.2 เกิดเมื่อไหร่

สถานการณ์ ตัวอย่าง note
Asynchronous input ปุ่มกด, switch มีโอกาสเกิด
ส่งสัญญาณข้าม clock domain SPI SCK 5 MHz เข้า FPGA ที่ clock 12 MHz มีโอกาสเกิด
Synchronous logic (register ต่อ register ใน clock domain เดียวกัน)

โดยปกติไม่มีปัญหา เพราะ tool คำนวณ timing ให้ ถ้า timing ผ่าน (setup/hold met) จะไม่เกิด metastability
แต่ถ้า tool รายงาน timing violation (slack ติดลบ) ก็มีโอกาสเกิดได้ เพราะแปลว่ามี path ที่ data อาจเปลี่ยนค่าในช่วง tSU/tH ของ FF

  • Setup violation เช่น Fmax ไม่ถึง, WNS < 0: path ช้าเกินคาบ clock ทำให้ data มาถึงไม่ทัน tSU
  • Hold violation เช่น WHS < 0: data เปลี่ยนเร็วเกินไปหลังขอบ clock จนไม่ถึง tH

3.3 แนวทางลดความเสี่ยง

แนวทาง รายละเอียด
Synchronizer (2 FF ขึ้นไป) ใช้กับสัญญาณ 1 บิต; ยิ่งเพิ่ม stage ยิ่งปลอดภัย แต่ latency เพิ่มตามจำนวน stage
อย่านำ async input 1 เส้นเข้า FF หลายตัว FF แต่ละตัวอาจ resolve ไม่เหมือนกัน ทำให้ระบบเห็นค่าไม่ตรงกัน
ให้ผ่าน synchronizer ก่อนแล้วค่อยกระจายไปใช้
FIFO (dual-clock) ใช้ข้ามข้อมูลหลายบิตระหว่าง clock domain
ข้อควรจำ

Metastability กำจัดให้เป็นศูนย์ไม่ได้ ทำได้เพียงลดความน่าจะเป็นที่จะเกิดความผิดพลาดให้ MTBF นานพอจนยอมรับได้ (เช่น หลายพันปี)

ตัวอย่าง Synchronizer 2FF ให้เอา sig_out ไปใช้งาน

จำนวน FF โครงสร้าง ความเสี่ยงที่จะเกิด Metastability MTBF โดยประมาณ Latency
0 FF Async → Logic 🔴 สูงมาก / ไม่มีการป้องกัน ต่ำที่สุด ~0 CLK
1 FF Async → FF0 → Logic มีโอกาสเกิด ต่ำ ~1 CLK
2 FF Async → FF0 → FF1 → Logic 🟢 ต่ำมาก สูงขึ้นแบบ Exponential ~2 CLK
3 FF Async → FF0 → FF1 → FF2 → Logic 🟢🟢 ต่ำมากยิ่งขึ้น สูงขึ้นแบบ Exponential อีก ~3 CLK
4 FF Async → FF0 → FF1 → FF2 → FF3 → Logic 🟢🟢🟢 Extremely low สูงขึ้นแบบ Exponential อีก ~4 CLK
MTBF คืออะไร

MTBF (Mean Time Between Failures) คือ เวลาเฉลี่ยระหว่างความผิดพลาด 2 ครั้ง ในที่นี้คือ ระยะเวลาเฉลี่ยที่ metastability จะหลุดไปทำให้ระบบผิดพลาดสักครั้ง

  • MTBF ยิ่งสูง ยิ่งปลอดภัย เช่น MTBF = 1,000 ปี แปลว่าโดยเฉลี่ยกว่าจะพังสักครั้งก็นานมาก
  • เป็นค่าเฉลี่ยทางสถิติ ไม่ใช่การรับประกันว่าจะไม่พังภายในช่วงเวลานั้น

3.4 ตัวอย่างวงจร edge detect

ตัวอย่างนี้เป็นการทำ edge detect ของสัญญาณ asynchronous โดยแก้ปัญหา metastability คือผ่านสัญญาณเข้า 2-FF synchronizer ก่อน แล้วค่อยนำค่าที่นิ่งแล้วไปตรวจจับขอบ (ถ้าตรวจขอบจากสัญญาณ async โดยตรง ไม่ผ่าน synchronizer FF อาจเกิด metastability ทำให้ detect ผิดพลาด)

4 CDC (Clock Domain Crossing)

ในการออกแบบระบบ FPGA ที่มีสัญญาณนาฬิกาตั้งแต่ 2 ความถี่ขึ้นไป (Multi-Clock Domains) ข้อมูลที่เดินทางข้ามขอบเขตสัญญาณนาฬิกา (Clock Domain) อาจเสี่ยงต่อการเกิด Metastability (สภาวะไม่เสถียร) เนื่องจากขัดต่อกฎ Setup/Hold Time

4.1 วิธีการจัดการสัญญาณข้าม Clock Domain (CDC Solutions) สามารถเลือกใช้ตามลักษณะของข้อมูลดังนี้:

ลักษณะสัญญาณข้อมูล (Data Characteristic) วิธีการจัดการ CDC ที่เหมาะสม คำอธิบายและพฤติกรรมฮาร์ดแวร์
1. สัญญาณ 1 บิต (Single-bit Signal)
(เช่น Enable, Flag, Pulse)		 2-Stage Flip-Flop Synchronizer ใช้ D Flip-Flop 2 ตัวต่ออนุกรมกันใน Clock Domain ปลายทาง เพื่อขจัดสภาวะ Metastability
2. สัญญาณหลายบิต (Multi-bit Vector)
(เช่น บัสข้อมูล, ตัวนับ Address)		 Gray Code Encoding เปลี่ยนการนับตัวเลขเป็น Gray Code (บิตเปลี่ยนเพียง 1 บิตต่อ State) ร่วมกับ 2-Stage Synchronizer
3. สัญญาณรับ-ส่งแบบมีจังหวะ
(Control Signal + Multi-bit Data)		 Handshake Protocol ใช้สัญญาณควบคุม Req (Request) และ Ack (Acknowledge) ตอบรับข้ามโดเมนก่อนส่งข้อมูล
4. ข้อมูลสตรีมความเร็วสูง
(High-Speed Data Stream / FIFO)		 Asynchronous FIFO ใช้ Async FIFO ที่มี Dual-Clock แยกฝั่งอ่าน-เขียน (wr_clk, rd_clk) โดยใช้ Gray Code Pointer ภายใน

4.2 📝 ตัวอย่างโค้ด VHDL สำหรับวิธียอดนิยม:

4.2.1 2-Stage Flip-Flop Synchronizer (สำหรับสัญญาณ 1 บิต)

library IEEE;
use IEEE.STD_LOGIC_1164.ALL;

entity cdc_2ff_sync is
    Port (
        dest_clk   : in  STD_LOGIC; -- Clock Domain ปลายทาง
        rst_n      : in  STD_LOGIC;
        i_async_sig: in  STD_LOGIC; -- สัญญาณ 1 บิต จาก Clock Domain ต้นทาง
        o_sync_sig : out STD_LOGIC  -- สัญญาณที่ถูก Sync แล้ว (เสถียรพร้อมใช้งาน)
    );
end cdc_2ff_sync;

architecture Behavioral of cdc_2ff_sync is
    -- Flip-Flop 2 Stage สำหรับกรอง Metastability
    signal r_ff1 : std_logic := '0';
    signal r_ff2 : std_logic := '0';
    
    -- กำหนด attribute ป้องกันการเกิด Register Optimization ใน Vivado
    attribute ASYNC_REG : string;
    attribute ASYNC_REG of r_ff1 : signal is "TRUE";
    attribute ASYNC_REG of r_ff2 : signal is "TRUE";
begin

    process(dest_clk, rst_n)
    begin
        if rst_n = '0' then
            r_ff1 <= '0';
            r_ff2 <= '0';
        elsif rising_edge(dest_clk) then
            r_ff1 <= i_async_sig; -- Stage 1: ซับ Metastability
            r_ff2 <= r_ff1;         -- Stage 2: ออกสัญญาณเสถียร
        end if;
    end process;

    o_sync_sig <= r_ff2;

end Behavioral;

4.2.2 Handshake Protocol (สำหรับบัสข้อมูลหลายบิต)

-- ขั้นตอน Handshake:
-- 1. ฝั่งส่ง (Domain A) ป้อน data และชูสัญญาณ Req = '1'
-- 2. ฝั่งรับ (Domain B) sync สัญญาณ Req เมื่อเห็น Req='1' จะบันทึก data และส่ง Ack = '1' ตอบกลับ
-- 3. ฝั่งส่ง Sync สัญญาณ Ack เมื่อเห็น Ack='1' จึงเคลียร์ Req = '0'
