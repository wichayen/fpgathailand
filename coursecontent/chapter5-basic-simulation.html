1 Simulation tool

ปัจจุบันมี Simulation Tools ให้เลือกใช้หลายตัว ทั้งแบบเสียเงินและฟรี แต่ละตัวมีจุดเด่นและข้อจำกัดต่างกันไป โดยสรุปรายละเอียดของแต่ละ Tool ไว้ในตารางด้านล่างนี้

1.1.1 ตารางสรุป FPGA Simulation Tools

เครื่องมือ (Simulator) ผู้พัฒนา (Vendor/Developer) ค่าใช้จ่าย (License Type) ภาษาที่รองรับ จุดเด่น / หมายเหตุ
Vivado XSim AMD / Xilinx ฟรี (อยู่ใน Vivado ML Standard Edition) VHDL, Verilog, SystemVerilog มาพร้อม Vivado GUI ใช้งานสะดวกกับชิป Xilinx
ModelSim (Intel/Altera Edition) Siemens EDA / Intel มีฟรี / เสียเงิน (Starter Edition ฟรี) VHDL, Verilog, SystemVerilog เป็นมาตรฐานอุตสาหกรรม เสถียรสูง
Questa Simulator Siemens EDA / Intel มีฟรี / เสียเงิน (Starter Edition ฟรีเมื่อลงทะเบียน) VHDL, Verilog, SystemVerilog, UVM ทดแทน ModelSim ใน Quartus Prime รุ่นใหม่ รองรับ UVM
GHDL Open-Source Community ฟรี 100% (Open-Source - GPL) VHDL Open-source VHDL simulator ที่ได้รับความนิยมสูงสุด
NVC Open-Source Community ฟรี 100% (Open-Source - GPL) VHDL (2008 เกือบครบ, 2019 บางส่วน) คอมไพล์เป็น native code ด้วย LLVM จำลองเร็วกว่า GHDL อย่างมีนัยสำคัญในหลายกรณี รองรับ VHDL-2019 ดีกว่า GHDL
Icarus Verilog (iverilog) Open-Source Community ฟรี 100% (Open-Source - GPL) Verilog / SystemVerilog (บางส่วน) เบา รันรวดเร็ว นิยมใช้ร่วมกับ GTKWave
Verilator Open-Source Community ฟรี 100% (Open-Source - LGPL) SystemVerilog / Verilog แปลง RTL เป็น C++ สปีดการจำลองรวดเร็วมาก นิยมทำ Co-simulation
Active-HDL Aldec เสียเงิน (มี Student Edition แจกบางเงื่อนไข) VHDL, Verilog, SystemVerilog มี GUI วิเคราะห์ waveform และ block diagram ที่ใช้งานง่าย
EDA Playground Doulos (Cloud-based) ฟรี (ใช้งานผ่าน Web Browser) VHDL, Verilog, SystemVerilog รัน Simulator ผ่านเว็บ ไม่ต้องติดตั้งโปรแกรม เหมาะกับการทดสอบสั้นๆ

1.1.2 หมวดหมู่เครื่องมือจำลอง (Simulator Categories)

1.1.2.1 Vendor-bundled / OEM Edition — ฟรีแต่ถูกจำกัด feature

เครื่องมือที่ผู้พัฒนาต้นทาง (เช่น Siemens EDA) อนุญาตให้ค่าย FPGA (Intel, AMD/Xilinx, Lattice, Microchip) นำไป customize และ bundle แถมมากับ IDE ของตัวเอง โดยผูกสิทธิ์การใช้งานไว้กับซอฟต์แวร์ค่ายนั้น

  • ตัวอย่าง:
    • Vivado XSim (AMD/Xilinx) — ฟรีเมื่อดาวน์โหลด Vivado ML Standard Edition ไม่ต้องใช้ License file สำหรับชิปรุ่นทั่วไป
    • ModelSim / Questa Intel FPGA Edition — ฟรีแต่ต้องลงทะเบียนขอ License File จาก Intel (Starter Edition จำกัดจำนวนบรรทัด code หรือความเร็วในการจำลอง)
    • ModelSim / Active-HDL Lattice Edition, ModelSim ME (Microsemi Edition)
  • ข้อดี: มีการ compile simulation library ของชิปค่ายนั้นๆ มาให้เรียบร้อยแล้ว พร้อมใช้งานทันที
  • ข้อจำกัด: ถูกล็อกให้จำลองการทำงานได้เฉพาะชิปของ vendor ค่ายนั้นๆ เท่านั้น (เช่น ModelSim Intel FPGA Edition จะนำไปใช้จำลองชิป Xilinx ไม่ได้) และมักจำกัด feature หรือขนาด design ใน Starter Edition
  • เหมาะกับ: งานเรียน, โปรเจกต์เล็ก-กลางที่ใช้ FPGA ค่ายเดียวตลอด

1.1.2.2 Open-source Standalone — ฟรีเต็มรูปแบบ ไม่ผูกค่าย

เครื่องมือ open-source ที่พัฒนาโดยชุมชนหรือผู้พัฒนาอิสระ ไม่สังกัดค่าย FPGA ใด ใช้ข้าม toolchain ได้อย่างอิสระ

  • ตัวอย่าง: GHDL, NVC (VHDL) / Icarus Verilog, Verilator (Verilog/SystemVerilog)
  • จุดเด่น: ไม่มีข้อจำกัดเรื่อง license, รันบน CI/CD ได้ง่าย, community พัฒนาต่อเนื่อง, เหมาะกับ workflow ร่วมกับ VUnit/OSVVM/cocotb และ GTKWave สำหรับดู waveform
  • ข้อควรระวัง: การรองรับมาตรฐานภาษาใหม่ๆ อาจตามหลัง commercial tool และแต่ละตัวมีจุดแข็งต่างกัน (เช่น GHDL เสถียรและนิยมสูงสุด แต่ NVC เร็วกว่าและรองรับ VHDL-2019 ดีกว่า) นอกจากนี้ถ้า design มีการเรียกใช้ primitive ของ vendor (เช่น IP core จาก Vivado IP Catalog) การ setting library ของ vendor ให้ใช้งานกับ GHDL/NVC ได้ ก็อาจมีความยุ่งยาก
  • เหมาะกับ: งานที่ไม่ต้องการผูกกับ vendor และไม่อยากมีปัญหาเรื่อง license (ทำ automated testing/CI ได้โดยไม่ติดข้อจำกัดเรื่อง license seat แต่ทุกกลุ่ม รวมถึง Commercial ก็ใช้ทำ CI/regression ได้เช่นกัน)

1.1.2.3 Commercial Standalone / Paid — เสียเงิน ระดับอุตสาหกรรม

ซอฟต์แวร์ simulator เต็มรูปแบบที่ผลิตและขายโดยผู้พัฒนาโดยตรง (ไม่ผ่าน OEM ค่ายใด) มี feature ครบสำหรับงาน verification ระดับอุตสาหกรรม

  • ตัวอย่าง: ModelSim PE/SE, Questa Base/Prime/Ultra (Siemens EDA), Active-HDL, Riviera-PRO (Aldec)
  • จุดเด่น: รองรับชิปและเทคโนโลยีของ FPGA ทุกค่าย (Xilinx, Intel, Lattice, Microchip) รวมถึงงาน ASIC, performance สูง, debug tool ครบ, รองรับ mixed-language และ UVM เต็มรูปแบบ ไม่มีขีดจำกัดด้านขนาดหรือความเร็ว
  • ข้อจำกัด: ราคาสูงมาก (commercial license) และผู้ใช้ต้อง compile simulation library ของแต่ละค่าย FPGA เองก่อนใช้งาน
  • เหมาะกับ: งานอุตสาหกรรม, ASIC/FPGA ขนาดใหญ่ที่ต้องการ verification methodology มาตรฐาน

ตารางสรุปเปรียบเทียบ

กลุ่ม ตัวอย่าง ค่าใช้จ่าย ผูกค่าย FPGA? เหมาะกับ
Vendor-bundled / OEM Vivado XSim, ModelSim/Questa Intel FPGA Edition ฟรี ใช่ งานเรียน/โปรเจกต์เล็ก
Open-source Standalone GHDL, NVC, Icarus Verilog, Verilator ฟรี ไม่ งานที่ไม่ต้องการผูกกับ vendor และไม่อยากมีปัญหาเรื่อง license
Commercial Standalone Questa, ModelSim PE/SE, Active-HDL, Riviera-PRO เสียเงิน ไม่ งานอุตสาหกรรม

2 เปรียบเทียบ Vivado XSim vs ModelSim/Questa

ในงานจริง XSim ยังไม่ได้มาแทนที่ ModelSim/Questa ทั้งหมด — ตัวเลือกที่เหมาะสมขึ้นอยู่กับ scope และระดับของงาน

2.1.1 ตารางเปรียบเทียบ

หัวข้อ Vivado XSim ModelSim / Questa
ค่าใช้จ่าย ฟรี (มาพร้อม Vivado ML Standard/WebPACK) ฟรีแบบจำกัด (Starter/OEM) หรือเสียเงิน (Standalone/Advanced)
การ Setup ใช้งานได้ทันที ไม่ต้อง compile library เพิ่ม ต้อง compile simulation library ของแต่ละ vendor เอง (โดยเฉพาะถ้าเป็น OEM edition ข้ามค่าย)
รองรับชิป เอียงไปทาง Xilinx/AMD เป็นหลัก รองรับทุกค่าย (Xilinx, Intel, Lattice, Microchip) รวมงาน ASIC
UVM รองรับ UVM 1.2 มาให้พร้อมใน Vivado โดยไม่ต้อง setup เพิ่ม รองรับ UVM เต็มรูปแบบเช่นกัน โดยเฉพาะ Questa Advanced ที่เป็นมาตรฐานงาน verification จริงจัง
GUI / Debug ใช้งานได้ แต่เน้น Tcl scripting มากกว่าเมื่อเทียบกับ ModelSim สำหรับ self-checking testbench GUI/waveform debugger เก่าแก่ ครบเครื่องกว่า หน้าต่างต่างๆ sync กันแบบ intuitive
Cross-platform / Cross-vendor ผูกกับ Vivado โดยตรง ใช้ข้าม tool ข้าม vendor ได้ เหมาะกับทีมที่ทำงานหลายค่ายพร้อมกัน
กลุ่มผู้ใช้หลัก ทีมขนาดเล็ก-กลางที่ทำงาน Xilinx ล้วนๆ, งานเรียน, การเริ่มต้นจำลองเร็วๆ academia, ทีม FPGA ขนาดเล็ก-กลาง (ModelSim) ไปจนถึงงาน verification ระดับอุตสาหกรรม/defense (Questa)
ความต้องการในตลาดงาน เริ่มถูกระบุในประกาศงานมากขึ้น แต่ยังไม่ใช่ requirement หลัก ยังถูกระบุเป็น requirement คู่กับ Xilinx tools ในประกาศงาน FPGA/Firmware หลายแห่ง
ข้อดี ไม่มีค่าใช้จ่าย, ไม่ต้อง compile library เพิ่ม, ผสาน workflow กับ Vivado ลื่นไหล (แก้โค้ด → รัน sim ได้ทันทีในเครื่องมือเดียว), เหมาะกับการเริ่มต้นเรียนรู้เร็ว GUI/waveform debugger ครบเครื่องและคุ้นเคยกว่าในสายงาน, ใช้ข้ามค่าย FPGA และงาน ASIC ได้, เป็น skill ที่ตลาดงานยังคาดหวัง, community/เอกสารสอนเยอะเพราะอยู่ในตลาดมานาน
ข้อเสีย ผูกกับ Xilinx/Vivado เป็นหลัก ใช้ข้ามค่ายไม่ได้, ต้องพึ่ง Tcl scripting มากกว่าเมื่อทำ self-checking testbench ที่ซับซ้อน, ยังไม่ใช่ requirement หลักในตลาดงานเท่า ModelSim/Questa รุ่นฟรี (Starter/OEM) ถูกจำกัด feature/ความเร็ว และผูกกับ vendor ที่แจก, ถ้าเป็น OEM edition ต้อง compile library เพิ่มเมื่อใช้ข้ามค่าย (ยุ่งยากตามที่แสดงในหัวข้อ 2.3), รุ่นเต็ม (Standalone) ราคาสูงมาก

2.1.2 AMD Vivado XSim

Vivado Simulator (XSim) เป็น simulator ที่ฝังมากับ Vivado โดยตรง ไม่ต้องตั้งค่า path หรือ compile library เพิ่มเติมสำหรับชิป Xilinx/AMD จึงเป็นตัวเลือกแรกที่เหมาะกับการเริ่มต้นจำลอง behavioral simulation

2.1.2.1 การจำลองผ่าน Vivado GUI (Project Mode)

  1. เตรียม Testbench — เขียนไฟล์ testbench (VHDL/Verilog) ที่ instantiate DUT (Design Under Test) แล้ว add เข้าโปรเจกต์ผ่าน Add Sources → Add or create simulation sources
  2. กำหนด Top Module ของ Simulation — ในหน้าต่าง Sources คลิกขวาที่ testbench แล้วเลือก Set as Top (เฉพาะใน simulation set เช่น sim_1 ไม่กระทบ synthesis top)
  3. รัน Simulation — คลิก Flow Navigator → SIMULATION → Run Simulation → Run Behavioral Simulation
    • Vivado จะ elaborate design แล้วเปิดหน้าต่าง XSim Waveform ให้อัตโนมัติ
  4. ควบคุมการจำลอง — ใช้ปุ่มใน waveform toolbar:
    • Run All — รันจนจบ testbench หรือจน stop/finish
    • Run For — กำหนดเวลาที่ต้องการรัน (เช่น 1000 ns) แล้วหยุด
    • Restart — reset การจำลองกลับไปเวลา 0 โดยไม่ต้อง re-elaborate ใหม่ทั้งหมด
  5. เพิ่มสัญญาณเข้า Waveform — ลาก signal จากหน้าต่าง Scope/Objects เข้า waveform window หรือคลิกขวา → Add to Wave Window

Note : Vivado รองรับการรัน simulation ได้หลายระดับ ขึ้นอยู่กับว่า design ผ่านขั้นตอนไหนมาแล้ว (RTL → Synthesis → Implementation) โดยหลักๆ ที่ใช้งานบ่อยที่สุดมี 3 แบบ:

ประเภท Delay อธิบาย
Run Behavioral Simulation ไม่มี delay จำลองจาก RTL โดยตรง เร็วที่สุด เหมาะกับการตรวจสอบ logic/functionality เบื้องต้น เป็นแบบที่ใช้บ่อยที่สุดระหว่างพัฒนาโค้ด
Run Post-Synthesis Timing Simulation มี delay (ประมาณการ) จำลองจาก netlist หลัง synthesis พร้อม annotate ค่า delay แบบประมาณการ (estimated) จากไฟล์ SDF
Run Post-Implementation Timing Simulation มี delay (ค่าจริงหลัง route) จำลองจาก netlist หลัง implementation ใช้ค่า delay จริงหลังจาก place & route แม่นยำที่สุด แต่ใช้เวลารันนานที่สุด
หมายเหตุ:

นอกจาก 3 แบบข้างต้น Vivado ยังมี Run Post-Synthesis Functional Simulation และ Run Post-Implementation Functional Simulation ให้เลือกด้วย ซึ่งจำลองจาก netlist หลัง synthesis/implementation เช่นกัน แต่ไม่ annotate ค่า delay (ไม่ต้องใช้ไฟล์ SDF) เหมาะกับการตรวจสอบว่า logic ยังทำงานถูกต้องหลัง synthesis/implementation โดยไม่สนใจเรื่อง timing

2.1.3 ModelSim Altera Edition สำหรับจำลองชิป AMD/Xilinx FPGA

ModelSim-Intel FPGA Edition (หรือชื่อเดิม ModelSim Altera Edition) เป็น OEM simulator ที่ผูกมากับ Quartus Prime โดยค่าเริ่มต้นจะมี simulation library ของ Intel/Altera ให้พร้อมใช้งาน(ไม่มี library ของ Xilinx ติดตั้งมาให้) เราสามารถนำมาใช้ simulate กับดีไซน์ที่มาจาก Vivado (ชิป AMD/Xilinx) แต่ว่าจะต้อง compile Xilinx simulation library เพิ่มเองก่อน

โดยสรุปมีขั้นตอนดังนี้
(ดูรายละเอียดได้จาก: https://wichayen.github.io/fpgathailand/pynq-z2-modelsim_th.html)

  1. Compile Xilinx Simulation Library ด้วย Modelsim
  2. Export Hardware ของ vivado projct
  3. แก้ไข compile.do ให้ครบสมบูรณ์
  4. ModelSim Altera Edition (do compile.do → do simulate.do)

ข้อควรทราบ: โดยปกติแล้ว AMD/Xilinx ไม่ได้ bundle ModelSim มาให้

3 Basic Simulation with ModelSim

หัวข้อนี้เป็นพื้นฐานการใช้งาน ModelSim ตั้งแต่สร้าง library, compile source, ไปจนถึงรัน simulation และดู waveform — ใช้ได้ทั้ง ModelSim Altera/Intel Edition และ ModelSim/Questa Standalone

3.1.1 โครงสร้างพื้นฐานของ ModelSim Workflow

การจำลองด้วย ModelSim มีขั้นตอนหลัก 4 ส่วนเสมอ ไม่ว่าจะรันผ่าน GUI หรือ command line:

  1. สร้าง Working Library — พื้นที่เก็บไฟล์ที่ compile แล้ว (เทียบเท่า xil_defaultlib ใน Vivado)
  2. Compile Source — แปลงไฟล์ VHDL/Verilog เข้า library
  3. Load Design (vsim) — โหลด design unit ที่ต้องการจำลอง (ปกติคือ testbench)
  4. Run & View Waveform — สั่งรันและดูผลลัพธ์

3.1.2 การจำลองผ่าน ModelSim GUI

  1. เปิด ModelSim แล้วสร้างโปรเจกต์ใหม่ผ่าน File → New → Project ตั้งชื่อและเลือก working directory

  1. Add Existing File — เพิ่มไฟล์ source (.vhd/.v) และไฟล์ testbench เข้าโปรเจกต์

  1. ไปที่เมนู Compile → Compile All
    (ถ้า compile ผ่าน จะเห็นเครื่องหมายถูกสีเขียวหน้าไฟล์ใน Project window)

  1. ไปที่เมนู Simulate → Start Simulation จากนั้นเลือกไปที่ work.tb_glitch_demo (testbench ของเรา) แล้วกด OK

  1. เพิ่มสัญญาณเข้า waveform: ลาก signal จากหน้าต่าง Objects เข้า Wave window หรือคลิกขวา → Add to → Wave → Selected Signals
  2. สั่งรันการจำลองที่ Transcript หรือปุ่ม toolbar:
    • run 1us — รันตามเวลาที่กำหนด

3.1.3 การจำลองผ่าน Command Line / Transcript และไฟล์ .do Script

ModelSim มี Tcl (Tool Command Language) เป็นภาษา script หลักสำหรับควบคุมการทำงานทั้งหมด ไม่ว่าจะเป็นการสร้าง library, compile, โหลด design, หรือสั่งรัน simulation เป็นภาษา scripting ทั่วไปที่ EDA tool หลายเจ้านิยมใช้ (รวมถึง Vivado ด้วย) เพราะเขียนสั้น กระชับ และเรียกใช้คำสั่งของ tool ได้โดยตรง วิธีนี้เหมาะสำหรับการเขียน script อัตโนมัติหรือรันแบบ batch โดยไม่ต้องเปิด GUI
คำสั่ง Tcl ของ ModelSim ถ้าต้องการดูคำสั่งทั้งหมดแบบละเอียด แนะนำให้ไปดูใน Reference Manual ของ ModelSim/Questa โดยตรง (เปิดได้จากเมนู Help → Tcl Man Pages ในโปรแกรม หรือค้นจาก command เฉพาะที่ต้องการในเอกสาร)

ด้านล่างเป็นตัวอย่างในการสร้าง simulation project:

# ==============================================================================
# ModelSim / QuestaSim Simulation Script
# Compares Ideal (Zero-Delay) vs Real Delayed (Glitch) behavior simultaneously.
# How to run:
#   In ModelSim transcript console: do sim.do
# ==============================================================================

# 1. Quit any running simulation
quit -sim

# 2. Clean and create work library
if [file exists work] {
    vdel -lib work -all
}
vlib work
vmap work work

# 3. Compile VHDL source files
vcom -2008 -work work glitch_demo.vhd
vcom -2008 -work work tb_glitch_demo.vhd

# 4. Start simulation with 1ps timing precision
vsim -t 1ps -novopt work.tb_glitch_demo

# 5. Configure Waveform Viewer
delete wave *

add wave -divider "CLOCK & RESET"
add wave -color "Yellow" -itemcolor "Yellow" /tb_glitch_demo/clk
add wave -color "White"  -itemcolor "White"  /tb_glitch_demo/rst_n

add wave -divider "INPUT STIMULUS"
add wave -color "Cyan"   -itemcolor "Cyan"   /tb_glitch_demo/d_in

add wave -divider "INTERNAL DELAYED SIGNALS (PHYSICAL MODEL)"
add wave -color "Gray"   -itemcolor "Gray"   /tb_glitch_demo/dut_delay/inv1
add wave -color "Gray"   -itemcolor "Gray"   /tb_glitch_demo/dut_delay/inv2
add wave -color "Orange" -itemcolor "Orange" /tb_glitch_demo/dut_delay/d_not

add wave -divider "IDEAL RTL OUTPUTS (ZERO DELAY)"
add wave -color "Cyan"   -itemcolor "Cyan"   /tb_glitch_demo/y_glitch
add wave -color "Green"  -itemcolor "Green"  /tb_glitch_demo/y_clean

add wave -divider "REAL FPGA OUTPUTS (WITH DELAY & GLITCH)"
add wave -color "Red"    -itemcolor "Red"    /tb_glitch_demo/y_glitch_delay
add wave -color "Green"  -itemcolor "Green"  /tb_glitch_demo/y_clean_delay

# 6. Run simulation
run 350 ns

# 7. Fit waveform into window
wave zoomfull

คำอธิบาย

  • quit -sim — ปิด simulation เดิมที่ค้างอยู่ก่อน (ถ้ามี) กันไม่ให้ error ตอนสั่ง vsim ใหม่ทับของเดิม
  • if [file exists work] { vdel -lib work -all } — เช็คว่ามี library work เก่าอยู่ไหม ถ้ามีให้ลบทิ้งก่อน เพื่อ compile ใหม่แบบ clean ทุกครั้ง
  • vlib / vmap — สร้าง library ใหม่ชื่อ work แล้ว map ให้ใช้งานได้ (ต้องทำก่อนเสมอถ้ายังไม่มี work library)
  • vcom -2008 -work work — compile ไฟล์ VHDL เข้า library work โดยบังคับใช้มาตรฐาน VHDL-2008
  • vsim -t 1ps -novopt — โหลดและ elaborate design พร้อมเปิด simulation kernel โดย
    -t 1ps กำหนดความละเอียดเวลา (time resolution) ของ simulator เป็น 1 ps ส่วน
    -novopt คือปิดการทำ optimization ตอน elaborate เพื่อไม่ให้สัญญาณภายใน (เช่น /dut_delay/inv1, /dut_delay/inv2) ถูกตัดทิ้งไปจนดูไม่ได้
  • delete wave * — เคลียร์ waveform window ให้ว่างก่อน เผื่อมี signal เก่าค้างจากการรันครั้งก่อน
  • add wave -divider "ชื่อกลุ่ม" — ใส่เส้นแบ่งกลุ่มสัญญาณใน waveform ให้อ่านง่ายขึ้น (เช่น แยกกลุ่ม Clock/Reset, Input, Internal Signal, Output)
  • add wave -color "..." -itemcolor "..." <path/to/signal> — เพิ่มสัญญาณที่ต้องการดูแบบเจาะจงทีละเส้น พร้อมกำหนดสีให้ต่างกันเพื่อแยกแยะง่าย
  • run 350 ns — รันจำลองเป็นเวลา 350 นาโนวินาที
  • wave zoomfull — ปรับ waveform window ให้ fit พอดีกับช่วงเวลาที่รันไปทั้งหมดโดยอัตโนมัติ ไม่ต้อง zoom เอง

วิธีรัน Script

คำสั่งทั้งหมดข้างต้นเก็บไว้ในไฟล์ sim.do :

  1. เปิด ModelSim ขึ้นมา (ยังไม่ต้องเปิดโปรเจกต์ก็ได้)
  2. ที่ Transcript window ให้ cd ไปยัง path ที่เก็บไฟล์ sim.do และไฟล์ source ทั้งหมดไว้ก่อน เช่น: 
    ModelSim> cd D:/github/FPGACourse/workshop/ws_glitch
  3. สั่งรัน script ด้วยคำสั่ง do ตามด้วยชื่อไฟล์: 
    ModelSim> do sim.do
    ModelSim จะรันคำสั่งทั้งหมดในไฟล์ตามลำดับให้อัตโนมัติ

Batch Mode (ไม่เปิด GUI)

นอกจากรันผ่าน Transcript window ใน GUI แล้ว เรายังสามารถรันแบบ batch mode คือไม่เปิด GUI เลยได้ (เหมาะกับ CI/CD หรือ regression test) โดยเปิด Command Prompt หรือ PowerShell ขึ้นมา แล้ว cd ไปยัง path ที่เก็บไฟล์ sim.do และไฟล์ source ทั้งหมด (เช่นเดียวกับตอนรันใน Transcript) จากนั้นสั่ง:

vsim -c -do "sim.do; quit -f"
  • -c — รันแบบ console-only ไม่เปิด GUI
  • quit -f — ปิดโปรแกรมทันทีหลัง simulation เสร็จ (จำเป็นสำหรับ batch mode เพื่อไม่ให้ค้างรอ)
