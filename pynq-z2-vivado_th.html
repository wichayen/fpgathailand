Vivado

1.   Vivado

1.1.  การสร้าง AXI IP ของตัวเอง

 

1.   เปิด Vivado แล้วสร้างโปรเจกต์ขึ้นมาใหม่ (ในตัวอย่างนี้จะตั้งชื่อโปรเจกต์ว่า project_1) 

2.   สร้าง IP

คลิกที่ Tools -> Create and Package New IP

 

เลือก Create a new AXI4 peripheral

 

        กำหนดชื่อ IP ตามต้องการ (ในตัวอย่างนี้จะใช้ชื่อว่า myip)

        ในส่วน Interface สามารถเพิ่มอินเทอร์เฟซ AXI และกำหนดจำนวนรีจิสเตอร์ที่ต้องการได้ โดยในตัวอย่างนี้จะสร้างเป็น IP แบบพื้นฐานโดยใช้การตั้งค่าเริ่มต้น (AXI-Lite)

        หากติ๊กเลือก Verify Peripheral IP using AXI4 VIP ระบบจะสร้างสภาพแวดล้อมและ Testbench สำหรับการจำลอง (Simulation) ให้โดยอัตโนมัติ


เมื่อตั้งค่าสภาพแวดล้อมเสร็จแล้ว ระบบจะสร้างโปรเจกต์สำหรับ Simulation ขึ้นมาดังภาพด้านล่าง

        จากนั้นใน IP Catalog จะมี myip_v1.0 ถูกเพิ่มเข้ามาพร้อมใช้งาน

 ※ หากต้องการเปลี่ยน IP หรือสลับไฟล์ Top สำหรับการจำลอง ให้คลิกขวาที่ไฟล์จำลองภายใต้ Simulation Sources ในหน้าต่าง Sources แล้วเลือก Set as Top จากนั้นคลิกขวาที่ sim_1 ใน Sources แล้วเลือก Run Simulation -> Run Behavioral Simulation

 

 

1.2.  การแก้ไข IP ที่สร้างขึ้น


ไฟล์ HDL ของ IP ที่สร้างขึ้นโดยอัตโนมัติจะถูกบันทึกไว้ที่ ./ip_repo/myip_1.0/hdl

        ในตัวอย่างนี้ เราจะเพิ่มพอร์ตเอาต์พุตชื่อ myip_out โดยเข้าไปเพิ่มสัญญาณเอาต์พุตในโมดูล myip_v1_0_S00_AXI.v ดังนี้

 

※ ภาษา HDL ที่ระบบสร้างขึ้นจะแตกต่างกันไปตามการตั้งค่าโปรเจกต์ของ Vivado ซึ่งสามารถเลือกเป็น Verilog หรือ VHDL ได้ที่ Settings -> General -> Target language

        จากนั้น ให้เพิ่มพอร์ตเอาต์พุต myip_out ในโมดูลระดับบน myip_v1_0.v เพื่อเชื่อมต่อสัญญาณออกมาด้านนอก ดังนี้


        ในหน้าต่าง IP Catalog ให้คลิกขวาที่ myip_v1.0 แล้วเลือก Edit in IP Packager

       

        คลิก OK เพื่อดำเนินการต่อ

        ระบบจะเปิดหน้าต่าง Vivado ขึ้นมาอีกหน้าต่างหนึ่งโดยอัตโนมัติ ให้ไปที่ Ports and Interfaces แล้วคลิก Merge changes from Ports and Interfaces Wizard เพื่ออัปเดตพอร์ตใหม่

 

        คลิกที่แถบ Review and Package แล้วคลิก Re-Package IP เพื่ออัปเดตแพ็กเกจ IP จากนั้นปิดหน้าต่าง Vivado ที่ใช้แก้ไข IP แล้วสลับกลับไปยังโปรเจกต์ Vivado หลัก

        ดับเบิลคลิกที่ myip_1_0_bfm_1_i ใต้ Design Sources เพื่อเปิด Block Design

 

        คลิกที่ Show IP Status แล้วกด Upgrade myip_v1_0_bfm_1 เพื่ออัปเดต IP ให้เป็นเวอร์ชันล่าสุด

        เมื่ออัปเดตแล้ว พอร์ต myip_out จะปรากฏขึ้นมา ให้คลิกขวาที่ myip_out แล้วเลือก Make External เพื่อดึงพอร์ตออกเป็นพอร์ตภายนอก

       

        เมื่อต้องการเริ่มการจำลองใหม่ ให้คลิกขวาที่ sim_1 ในหน้าต่าง Sources แล้วเลือก Run Simulation -> Run Behavioral Simulation

        จะเห็นว่าสัญญาณ myip_out ถูกเพิ่มเข้าไปในโมดูล DUT (myip_v1_0_bfm) ของการจำลองเรียบร้อยแล้ว

ตั้งชื่อ Block Design (ในตัวอย่างนี้ใช้ชื่อเริ่มต้นคือ design_1)

คลิก Add IP (+) แล้วเลือกเพิ่ม ZYNQ7 Processing System

 

คลิก Add IP (+) แล้วเลือกเพิ่ม myip ที่เราสร้างขึ้น

 ทำการเชื่อมต่อ Block เข้าด้วยกัน (หากคลิก Run Connection Automation ระบบจะช่วยเชื่อมต่อบัสและสัญญาณให้อัตโนมัติ แต่หลังจากเชื่อมต่อเสร็จแล้วควรตรวจสอบความถูกต้องอีกครั้ง)

 

ในบล็อกของ myip ให้คลิกขวาที่พอร์ต myip_out แล้วเลือก Make External เพื่อดึงสัญญาณออกไปเป็นพอร์ตภายนอกของ Block Design โดยอัตโนมัติ

 

ตรวจสอบและกำหนดตำแหน่งแอดเดรส (Address Map) ของ myip ในแถบ Address Editor

 

ในหน้าต่าง Sources ภายใต้ Design Sources ให้คลิกขวาที่ design_1 แล้วเลือก Create HDL Wrapper เพื่อสร้างไฟล์ Top Wrapper ของ Block Design โดยอัตโนมัติ

 สร้างไฟล์ Top ระดับบนสุดของ FPGA เพื่อเชื่อมต่อสัญญาณภายนอกเข้ากับ Block Design ที่สร้าง Wrapper ไว้ (ในตัวอย่างนี้จะสร้างไฟล์ prj_top.v ขึ้นมาเป็นไฟล์ TOP)

เพิ่มไฟล์ prj_top.v เข้าไปในโปรเจกต์ Vivado จากนั้นไปที่ Sources -> Design Sources -> คลิกขวาที่ prj_top แล้วเลือก Set as Top

รูปแบบคำสั่งพื้นฐานในการควบคุม Zynq VIP มีดังนี้:

1.7.  การตรวจสอบ IP ด้วย Chipscope (Logic Analyzer)

 

สั่ง Run Synthesis 1 รอบ เพื่อสังเคราะห์วงจร

 

เมื่อสังเคราะห์เสร็จแล้ว คลิกที่ SYNTHESIS -> Open Synthesized Design -> Set Up Debug

คลิก Find Nets to Add แล้วค้นหาสัญญาณที่ต้องการจับมาตรวจสอบ จากนั้นกดเพิ่มลงในรายการ

 

ในช่อง Clock Domain ของแต่ละสัญญาณ ให้คลิกขวาแล้วเลือก Sampling Clock ที่จะใช้จับสัญญาณ

 


จากนั้น ดำเนินการต่อไปยังขั้นตอน Run Implementation และ Generate Bitstream

 เปิด Hardware Manager แล้วคลิก Open Target -> Auto Connect เพื่อเชื่อมต่อกับบอร์ด

 คลิก Program Device เพื่อดาวน์โหลด Bitstream ลงสู่วงจร FPGA (ฝั่ง PL ของ Zynq)

 

ตั้งค่าเงื่อนไข Trigger setup เช่นเดียวกับการใช้งาน Logic Analyzer ทั่วไป

 

สั่ง Run Trigger เมื่อสัญญาณตรวจจับเงื่อนไข Trigger ได้ รูปคลื่นสัญญาณจะแสดงขึ้นมาดังรูปด้านล่าง

1.9.  แนะนำสภาพแวดล้อม Jupyter สำหรับการดีบัก IP ที่สร้างเองบนอุปกรณ์จริง

 

การดีบัก IP ที่สร้างขึ้นเองบนอุปกรณ์จริงโดยทั่วไปจำเป็นต้องมี U-Boot หรือเขียนโปรแกรมดีบักขึ้นมา ซึ่งต้องใช้เวลาและขั้นตอนในการเตรียมการค่อนข้างมาก ในหัวข้อนี้จึงขอแนะนำวิธีดีบักที่สะดวกและรวดเร็วกว่า โดยใช้สภาพแวดล้อม Jupyter Notebook บน PYNQ

"Jupyter Notebook" คือสภาพแวดล้อมการพัฒนาที่สามารถเขียนและรันโปรแกรมผ่านเว็บเบราว์เซอร์ได้ (โดยทั่วไปจะรันอยู่บน PC) แต่สำหรับชิป Zynq นั้นมีโอเพนซอร์สเฟรมเวิร์กที่ชื่อว่า PYNQ (Python Productivity for Zynq) ซึ่งรันระบบปฏิบัติการ Linux บนฝั่ง Processing System (PS) ของ Zynq และเปิดเซอร์วิส Jupyter ทำงานอยู่ ทำให้เราสามารถเขียนสคริปต์ Python ผ่านเว็บเบราว์เซอร์เพื่อเข้าถึงและควบคุมวงจรบนฝั่ง FPGA (PL) ได้โดยตรง

บอร์ดที่รองรับสภาพแวดล้อม PYNQ สามารถดูรายการได้ที่ http://www.pynq.io/board.html

 

การเตรียมสภาพแวดล้อมมีดังนี้: ให้เชื่อมต่อบอร์ด Zynq และเครื่อง PC ให้อยู่ในเครือข่ายวงเดียวกันผ่านเราเตอร์/สวิตช์ จากนั้นต่อสาย USB สำหรับ JTAG Debugger จาก PC เข้ากับพินดีบักของบอร์ด Zynq และต่อสาย UART Serial เพื่อดูคอนโซลของ Linux บนเครื่อง PC


ขั้นตอนการดีบัก:

1. เปิดสวิตช์เปิดเครื่องบอร์ด แล้วรอจนกว่า Linux จะบูตเสร็จสมบูรณ์ จากนั้นพิมพ์คำสั่ง ifconfig บนเทอร์มินัลเพื่อตรวจสอบ IP Address ของบอร์ด Zynq (เช่น ได้ IP เป็น 192.168.1.55)

 

2. เปิดเบราว์เซอร์บน PC แล้วป้อน IP Address ดังกล่าวเพื่อเข้าสู่หน้าเว็บ Jupyter Notebook (รหัสผ่านเริ่มต้นสำหรับเข้าสู่ระบบคือ "xilinx")

 

3. สลับกลับไปที่ Vivado แล้วคลิก Program Device เพื่อดาวน์โหลด Bitstream กำหนดค่า FPGA ทางฝั่ง PL ของ Zynq

4. กลับมาที่หน้าจอ Jupyter Notebook แล้วคลิก New -> Python 3 เพื่อเปิดโน้ตบุ๊กใหม่

 

5. เขียนโค้ด Python ตามตัวอย่างด้านล่าง เพื่อเข้าถึงรีจิสเตอร์ฝั่ง FPGA (PL) ได้โดยตรง:

• mmio = pynq.MMIO(...) ใช้กำหนดค่า Base Address และขนาดพื้นที่การเข้าถึงรีจิสเตอร์

• mmio.write(offset, data) ใช้เขียนข้อมูลลงในรีจิสเตอร์ตาม Offset ที่กำหนด

• mmio.read(offset) ใช้อ่านข้อมูลจากรีจิสเตอร์ตาม Offset ที่กำหนด

 

※ ข้อแนะนำ: สามารถใช้ Chipscope / Logic Analyzer ตรวจสอบรูปคลื่นสัญญาณควบคู่ไปด้วย เพื่อดูว่ามีการเข้าถึงรีจิสเตอร์บนฮาร์ดแวร์จริงตามที่สั่งจาก Python หรือไม่

 

※ หมายเหตุ: ในกรณีที่ออกแบบและพัฒนาบอร์ดขึ้นมาเอง จำเป็นต้องพอร์ต PYNQ/Linux ให้รองรับกับตัวบอร์ดก่อน ซึ่งแม้การพอร์ตจะใช้เวลาในช่วงแรก แต่เมื่อพร้อมใช้งานแล้ว จะสามารถเข้าถึงรีจิสเตอร์ได้อย่างอิสระด้วยสคริปต์ Python ตามวิธีที่แนะนำข้างต้น ช่วยให้การดีบักฮาร์ดแวร์สะดวกรวดเร็วขึ้นมาก

1.10.  เพิ่มเติม 1: การนำบัส AXI ออกไปนอก Block Design

 

หากต้องการเพิ่มพอร์ตสำหรับบัส AXI Master ให้เพิ่มจำนวน Master Interfaces ของ AXI Interconnect (เช่น เปลี่ยนจาก 1 เป็น 2)

       

        ในตัวอย่างนี้ เพื่อให้ได้บัสแบบ AXI-Lite ออกมาใช้งาน จะทำการเพิ่มบล็อก AXI Protocol Converter เพื่อแปลงโปรโตคอลจาก AXI ให้เป็น AXI-Lite

 

        ดับเบิลคลิกที่ AXI Protocol Converter แล้วตั้งค่า Address width (ในตัวอย่างนี้กำหนดเป็น 12 บิต)

 

        คลิกขวาที่พอร์ตอินเทอร์เฟซ M_AXI ของ AXI Protocol Converter แล้วเลือก Make External เพื่อส่งสัญญาณออกเป็นพอร์ตภายนอก

 

        จากนั้น สัญญาณของบัส M_AXI_0 จะถูกนำออกไปภายนอก Block Design

        กำหนดค่า Address Map สำหรับบัส AXI (M_AXI_0) ที่จะส่งออกไปข้างนอกในแถบ Address Editor

       

        ในการส่งสัญญาณ CLK และ Reset ออกไปนอก Block Design พร้อมกับบัส AXI ให้คลิกขวาบนหน้าจอ Block Design แล้วเลือก Create Port เพื่อสร้างสัญญาณ CLK และ Reset

        กำหนดค่าพอร์ตสัญญาณ CLK และ Reset ตามตัวอย่างด้านล่าง

        เมื่อคลิก Validate Design จะเกิดข้อผิดพลาดดังภาพ (เนื่องจากบัส M_AXI_0 ยังไม่ได้ผูกสัญญาณ CLK ที่เกี่ยวข้องไว้)

 

        วิธีแก้ไขข้อผิดพลาด ให้คลิกที่ M_CLK_0_CLK แล้วในส่วน CONFIG ของ Properties ให้ระบุ M_AXI_0 ในช่อง ASSOCIATED_BUSIF จากนั้นเมื่อทำการ Validate Design อีกครั้ง ข้อผิดพลาดจะหายไป

คลิกขวาที่ design_1 แล้วเลือก Create HDL Wrapper เพื่อสร้างไฟล์ Wrapper ใหม่

        จากนั้น สัญญาณของพอร์ตบัส M_AXI_0 จะปรากฏขึ้นใน Wrapper ดังนี้

นำสัญญาณบัส M_AXI_0 ไปเชื่อมต่อเข้ากับ Custom AXI IP ในไฟล์ Top ของโปรเจกต์

        เพิ่มคำสั่งการเข้าถึงแบบเขียน/อ่าน (Read/Write Access) ใน Testbench ของการจำลองไปยังตำแหน่ง Address ที่แมปไว้สำหรับ M_AXI_0

        เมื่อทำการจำลอง จะสามารถตรวจสอบการทำงานของ Custom AXI IP ที่เราสร้างขึ้นได้
